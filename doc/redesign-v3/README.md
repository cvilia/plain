## 方向是什么

**Quiet Ledger · 安静的账本。**

一句话：**一个记账本不该长得像一张仪表盘。**

| 四条定调 | 具体含义 |
| --- | --- |
| ① 中性层干净，**不要暖** | `bg`/`surface` 一律冷中性；light 下 `#F5F5F6` / 纯白 `#FFFFFF`；暗态最深 `#121214`（非纯黑）。**没有米黄、没有奶白、没有暖灰。** |
| ② **数字是唯一主角** | 8 级字阶里 4 级是金额；金额走**四段式**（货币符 0.62× / 整数 1× / 小数点 / 小数 0.62×）+ 等宽数字。一屏只允许一个最大字号。 |
| ③ **结构靠线与留白，不靠盒子** | 面板只用 1px `line` + `r16`；列表行**不上底色、不套淡彩底板**，靠 32px 留白分组。圆角只 4 档。 |
| ④ **色彩是语义不是装饰** | 彩色面积 ≤15%。12 个分类色只在**圆点**与**选择器图标**上出现；红绿**专用于涨跌**。 |

签名记忆点三处：**四段式金额** · **无底板的列表行** · **有实体键帽的键盘**。

## 比上一版好哪三点

### 1. 上一版是「暖纸 + 楷体 + 柔光」，这一版是素白底 + 无衬线 + 零光晕

上一版的 12 条失败点里，最重的是三项氛围错误：**米黄叠米黄**（底与卡片分不开）、
**楷体做标题**（与「可信、数字优先」的气质冲突）、**柔光球/渐变污渍**（把账本做成了壁纸）。

这一版：`surface` 一律**纯白**（不是奶白），标题走 **MiSans 700**（禁楷体），
首页 Hero 区**连卡片都没有** —— 只有上下两条 `hairline` 夹一个金额。
**强调靠排版对比，不靠背景装饰。**

### 2. 角色分工清楚了：圆点用于扫读，图标用于辨认；键盘有了实体键帽

上一版**每个列表行都套淡彩圆角图标底板** —— 12 个彩色方块把金额的注意力全抢走。
这一版把「图标」和「圆点」拆成两种语义：

- **流水行**（扫读场景）→ 8×8 **色点**，安静、不抢数字；
- **分类选择器**（辨认场景）→ 12 枚**分类图标**，显著缩短找分类的时间。

同时把「键盘无键帽」补上：每个键 = `surface-2` 底 + **1px 描边** + **1 层阴影**，
键高 62，保存键跨 2 列用 `accent` —— 键盘里唯一的色彩。

### 3. 交付的是**可验收的规格**，不是效果图：1168 项对比度门禁 + 100 枚可编译图标 + 8 屏可点高保真

上一版只交了「方向说明」。这一版：

| | 规模 | 验证方式 |
| --- | --- | --- |
| 令牌 | **20 组 × 53 字段** | 门禁 **1168 项全绿 / 0 失败**（`min_ratio 1.034`） |
| 图标 | **100 枚**，24 网格 / 1.75 描边 / `fill:none` | 码位 `0xE001`–`0xE064` 连续，文件一一对应（首轮 84 + 2026-10-14 追加 16） |
| 控件 | **25 节**解剖 + 状态表 | 每个控件都有 默认/按下/禁用/选中/焦点 |
| 屏幕 | **8 屏 × 亮暗 × 中英 × 主题 × 字号** | 可点可切的单文件 HTML + **38 张截图**（8 屏全四态覆盖） |
| 全量屏幕 | **29 屏**（V1.0 11 + V2.0 8 + V3.0 10） | `单独确认.html` 单文件 + **29 张截图**，逐屏 844 高度预算实测通过 |
| 规格标注 | **29 屏 × 2395 个元素** | `单独确认-标注版.html`，iPhone 16（393 × 852），位置 / 尺寸 / 圆角 / 颜色 / 间距逐项**实测**；字号越界 **0**、圆角越界 **0** |
| 字体 | MiSans 4 字重 | **实测 `document.fonts` 全 `loaded`**，数字宽 26.14 = 44×594/1000 |

而且**过程里抓出了三个只有实测才能发现的真 bug**（不是调参，是实现错误）：

1. **字体静默回退** —— 截图看着「差不多」，实际 `@font-face` 全部 `error`，字形根本不是 MiSans；
2. **图标被默认 fill 填黑** —— 内联 `<symbol>` 丢掉根节点 `fill="none"`，
   **每一枚含闭合路径的图标都变成实心黑块**，只有纯线条图标侥幸正常；
3. **记一笔键盘溢出 103px** —— 键盘第 4 行被切掉，且分类格第 3 行只有 1 个格子。

还有一条**把「米黄」的根因定位到了代码里**（`_build/_probe_drift.py`，只读）：

交付令牌与代码做了逐项漂移核对 —— **53 个字段名零差异、20 组品牌种子零差异、tone 分组零差异**，
只有中性层的**值**动了，且只动了一件事：**去暖**。
代码侧 `warm` 的页面底是 `#F6F1E8`、面板是 `#FCF8F1` —— **两个都是米黄**，
这正是「米黄叠米黄、面板与页面分不开」的来源。交付改成「页面留 3 度暖（R−B 从 +14 降到 +3）、面板纯白」。

> ⚠️ **这个差门禁查不出来**：改前 1.063 / 改后 1.080，**两者都过 1.02**。
> 问题在**色相重复**不在明度 —— 所以这条只能靠人守，见下方风险 1。

## 还有哪两点风险

### 风险 1：米黄是「氛围」最容易复发的地方，一旦回潮整套定调就散了

这套设计**没有氛围层**：没有光晕、没有渐变底、没有插画、没有纹理。
好处是干净，**代价是它对「底色的纯度」极度敏感** ——
任何一处往底色里加一点点暖（比如为了方便让 `surface` 用 `#FDFCFA` 而不是纯白），
「面板与页面分不开」的老问题会立刻回来，而且门禁**查不出来**（`layerstep` 只查明度差，不查色相）。

**守住的办法**：`surface` 必须是 `#FFFFFF`；三个 tone 的 `bg` 满足 **R−B ≤ 3**；
新增任何"氛围"元素前先问「它是否有信息量」。

### 风险 2：两处「本轮替产品做了决定」的地方还挂着，落地前必须拍板

这两处不是设计问题，是**越界风险** —— 我在没有产品确认的情况下动了结构：

| 待拍板 | 我做了什么 | 为什么要产品点头 |
| --- | --- | --- |
| **T-4** | 记一笔的**属性栏由 3 行改成 1 行 chip** | 这是为了把键盘第 4 行塞进 844 而做的**结构性改动**。三个 chip 各自打开原弹层、功能不变，但**用户的点击路径变短了**，属交互变更而非纯视觉 |
| **T-3** | ~~84 枚图标有**两条落地路线**（转图标字体 / `flutter_svg` 直读）~~ | **已定**：编码侧走 `flutter_svg` 路线，见《04》§5 拍板表 |

**另外两处口径分歧**（不改也能跑，但会一直硌着）：

- **T-1**：文档写 `AppTokens` 48 字段、**代码实为 53**。本轮令牌严格对齐 53，**文档该回改**；
- **T-7**：报表/资产的演示数据是**我编的但自洽**（占比合计 100%、金额合计对得上净资产），
  是否要换成 PRD 里的真实示例口径由你定。
