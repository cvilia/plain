## 2. 质量自检 19 项

### A. 令牌与对比度

**① 20 组令牌全绿**
`gates: {per_combo: 56, combos: 20, total: 1168, passed: 1168, failed: 0, min_ratio: 1.034}`
证据：`python _build/gen_tokens.py`

**② 应用界面内无裸色号**
剔除主题变量块后，页面还有 **17 处**裸色号 —— 但**全部落在脚手架**，不在设计系统内：

| 位置 | 处数 | 归属 |
| --- | --- | --- |
| `.toolbar` / `.seg2` / `.screenpicker` / `.tb-*` | 12 | 页面顶部工具条，**不参与设计系统** |
| `html,body{background:#E9E9EC}` | 1 | 手机帧背后的页面底衬 |
| `.flabel` 帧标签 | 2 | 脚手架 |
| `mask-image:... #000` | 2 | 遮罩色，不是设计色 |

结论：**8 屏应用界面内的每一处颜色都走 `var(--*)`**，色值只出现在 `theme_vars()` 生成的变量块里。
证据：见上方脚本（剔除 `body[data-theme][data-mode] .stage{...}` 四段后再匹配 `#RRGGBB`）

**③ 不变量 INV-1 成立**
12 分类基色与语义色跨 10 主题恒等（84 项单独校验，含在 1168 内）。

### B. 排版

### E. 图标

**⑮ 84 枚图标全为描边（本轮抓到的第二个重灾区）**
⚠️ `sprite()` 原本只取 `<svg>` 内部内容，**丢掉了根节点的 `fill="none"`**；
SVG 默认 `fill` 是**黑**，于是**每一枚含闭合路径的图标都被填成实心黑块**
（盾牌、锁、碗、购物袋全中招），只有纯开放路径的图标（导航那几条线）侥幸正常，
**肉眼极易漏过**。已修：`fill="none"` 搬到 `<symbol>` 上，并加**断言**——
源文件缺 `fill="none"` 直接报错，不再静默出黑块。
证据：`grep -c 'viewBox="0 0 24 24" fill="none"' 07-SCREENS.html` → **84 / 84**

**⑯ 图标清单与文件一一对应**
84 条记录 → 84 个 SVG，码位 `0xE001`–`0xE054` 唯一、名称唯一、无孤儿无缺失。

**⑰ 无 emoji / 无汉字图标 / 无 Material 默认皮**
`07-SCREENS.html` 里不出现任何 Material Icons 引用；所有图标来自 `04-ICON-SYSTEM/svg/`。

### 3.1 字体静默回退（最严重）

| 项 | 内容 |
| --- | --- |
| 现象 | 截图看着「差不多」，但字形不是 MiSans |
| 根因 | 截图临时 HTML 写在系统临时目录 → `@font-face` 相对路径 404 |
| 证据 | `document.fonts` 全部 `status=error` |
| 修法 | 临时 HTML 与 `07-SCREENS.html` 同目录；`shoot.py` 已加注释锁死 |
| 教训 | **字体加载失败是静默的**，必须显式断言 `document.fonts.check()` |

### 3.2 图标被默认 fill 填黑（波及全套）

见 §2-⑮。修法：`<symbol>` 带 `fill="none"` + 源文件断言。

### 3.3 记一笔键盘溢出 103px

| 项 | 首版 | 现在 |
| --- | --- | --- |

### 3.4 截图帧被响应式缩放

| 项 | 内容 |
| --- | --- |
| 现象 | 每张图下缘都有 152px 空白，内容只占 82% |

| 修法 | 截图侧用 `!important` 抵消；**页面那条规则保留**（真机窄屏下是正确行为） |

### 3.5 中英帧同时渲染

语言切换 CSS 只写了「默认隐藏中文帧」，**从未隐藏英文帧** → 网格模式下 16 帧而非 8 帧。
已改为「先全隐藏，再显示与 `body[data-lang]` 匹配的一半」。

### 3.6 `.rcol` 作用域未命中

`.row .rcol{flex-direction:column}` 只在 `.row` 下生效；分类管理用 `.crow2`，
导致「餐饮」与别名挤成一行 `餐饮三餐、外卖、堂食`。已改为独立类 `.rcol`。

### 3.7 环形图中心金额压环（**收尾复看截图才发现**）

第一轮 38 张出完后逐张复看，才发现报表屏的中心金额**压在圆环上** —— 归档前抓到，未流出。

| 项 | 首版 | 现在 |
| --- | --- | --- |
| 环 | 124×124 / R=46 / stroke 13 → **内孔 79** | **136×136 / R=52 / stroke 13 → 内孔 91** |
| 中心金额 | 单行 17px（非四段式） | **四段式**，整数 18px / `¥` 与小数 `.62em` |
| 可用宽 | 79 − 4 = **75** | 91 − 4 = **87** |
| `¥5,879.50` 实测宽 | **84.00 → 溢出 5px** | **77.53 → 左右各余 6.73** ✅ |
| 最坏值 `¥86,420.50` | 96.00 → 溢出 17px | 83.70 ✅ |

**根因**：环内孔是按「放 8 个字符」估的，没按 MiSans 真实度量算。

**取证方式**：先 `_build/_probe_donut.py` 用 fontTools 按 tnum 594/1000 算阈值表（不靠估），
改完再用 `_build/_probe_donut_live.py` 在真浏览器里 `getBBox()` 复测 ——
**推算与实测两次都做，才敢说「不压了」**。

⚠️ 顺带修正一个度量坑：MiSans 数字的**比例宽度 `0` 是 661/1000，tnum 才是 594**。
按比例宽度算会**多算约 11%**，把「其实放得下」判成放不下。

2. **`<use href>` 指向不存在的 symbol 同样静默**（a 条）。这条**在上一轮就存在于已交付物里**，

### 3.10 应对：`gen_all_screens.py` 内置写盘门禁 `guard()`

针对 3.9 的三个系统性风险，已在生成器里加了**不可绕过的写盘前自检**：

| 检查项 | 判定 | 失败后果 |
| --- | --- | --- |
| `var(--x)` 的 `x` 是否都已定义 | 全文扫 `--x:` 定义集合 ∩ `var(--x)` 引用集合 | **拒绝写盘**，逐条打印未定义变量名，`exit 1` |
| `<use href="#x">` 是否有对应 `<symbol id="x">` | 同上 | **拒绝写盘**，逐条打印悬空引用，`exit 1` |

通过时打印 `guard: ok`。**这意味着这两类静默失败从此不可能进交付物** ——
而非"多看一眼"。当前状态：`screens: 29` + `guard: ok`（0 违规）。

> 这两条门禁**专治"看起来没问题"**：浏览器不会因为变量名写错而报错，
> 只会安静地把颜色换成 `transparent` 或把事情换成空白。人眼能漏，脚本不会。

金额 0.62× 派生字号（本版实测 108 处，属文档规定的合法值）。

**标注版的形态**：
- 画布 1:1 真渲染 + 控件描边（按类型着色）+ **角标序号**（与表一一对应）；
- 左侧虚线＝**控件之间的纵向间距**（只画浅层、≥4px 的）；分割线在画布上**用品红单独描出**；
- 右侧**逐行规格表**：`# / 元素 / 位置 x,y / 尺寸 宽×高 / 圆角 / 填充·边框 / 文字·字号·字重·颜色 / 间距`，
  按父子关系缩进，颜色同时给出 **hex 与令牌名**；
- 悬停联动（表 ↔ 画布互为高亮）；可按类型筛选 / 搜 class / 跳屏 / 只标首屏；
- **越出屏幕下缘的元素**：描边框裁到屏幕边缘（不画到机身外），右下留品红 **▾** 提示「后面还有内容」，
  真实高度以表为准。实测 **35 处**（滚动内容的自然溢出，例如 SP-1-03 的分类面板高 866、起始 y=151）。

**栽过的两个坑（都已记进生成器注释 + 自检脚本）**：

1. **`border` 压低基准**：给 `.frame` 加 `border:1px` 做描边，会把内容盒从 393×852 压成 **391×850**
   —— 而 `spec.json` 是按 393×852 实测的，叠加层当场与渲染错位 2px。改用 `box-shadow` 描环（不影响布局）。
2. **描边框溢出机身**：`.screen` 自己 `overflow:hidden`，但叠加层挂在 `.frame` 上、而 `.frame` 是
   `overflow:visible` —— 滚动内容的框直接画到机身外，实测第 5 屏 4 个框越界、最远**下溢 165px**
   （第 9 屏单框下溢 613px）。修法：框与角标收进 `.ovclip{position:absolute;inset:0;overflow:hidden}`；
   `.ovl` 本身不能裁（左侧尺寸线画在 `left:-30px`，要露在机身外），所以只裁框、不裁尺寸线。

⚠️ **验证「有没有画到机身外」不能用 `getBoundingClientRect` 比机身矩形** —— `overflow:hidden`
只裁**绘制**，布局盒仍是全尺寸，这么量永远报「越界」（这条弯路走过一次）。
真正的不变式是：**每个 `.ov` 都必须处在一个与机身等大、且 `overflow:hidden` 的 `.ovclip` 里**，
`_probe_ann.py` 现在按这个断言，并核对 `▾` 标记数 == 越下缘元素数。

**数值一致性抽查**（`_probe_ann.py`，真浏览器）：
29 屏 / 2395 行 / 2234 个画布框与角标 / 152 条尺寸线 / 22 条分割线（**全为高 1px**）/ `JS_ERRORS=none`；
`frame = screen = 393 × 852`；**逐屏核对通过**：2234 个画布框的 inline 几何与表内 `x/y/w/h`
**逐项相等**，横向无越界；圆角实测枚举 `{8, 12, 16, 999, 50%, 4 4 0 0}` **全部合法**。
抽查第 1 屏第 2 号元素，画布框 `24px,0px 345×47` 与表内 `24, 0 | 345 × 47` **完全一致**。
