## 1 · 本轮交付原则：设计 = 可实现的规格 + 可用的资源

上一版失败的另一个根因是：**只聊了感觉，没交资产与规格**。  
UI 不只是颜色和效果图，而是一整套可编码的东西：

| 层 | 必须交付什么 | 我实现时怎么用 |
| --- | --- | --- |
| 资源层 | 图标 SVG 全套、（可选）插画/空态图 | 直接进 `assets/`，转图标字体或用 `flutter_svg` |
| 令牌层 | 色值 / 字体 / 字号字重 / 间距 / 圆角 / 阴影 / 动效 | 映射到 `AppTokens` 与 Theme |
| 控件层 | 每个控件的尺寸、内边距、圆角、描边、触控区、状态 | 重写 `design_system/*` |
| 交互层 | 按压、禁用、选中、焦点、加载、转场、手势 | 写 GestureDetector / Animation / Hero |
| 屏幕层 | 8 屏布局：区块位置、顺序、留白 | 重写 feature 页面 |

## 2 · UI 设计应当遵循的规范（设计师口径）

### A. 信息与层级
| # | 规范 | 落地要求 |
| --- | --- | --- |
| A1 | 一屏一重点 | 任意一屏只允许 1 个视觉焦点 |
| A2 | 层级四手段 | 字号 / 字重 / 色阶 / 留白 |
| A3 | 读序可预测 | 金额 → 标题 → 次要 → 操作 |
| A4 | 密度有节奏 | 组间留白 ≥ 组内间距 |

### B. 排版（必须给出完整字阶表）
| # | 规范 | 落地要求 |
| --- | --- | --- |
| B1 | 字阶封闭 | 6–8 级，每级写清：字号 / 字重 / 行高 / 字距 / 色token / 用途 |
| B2 | 行高随文种 | 中文 1.5–1.7，西文 1.3–1.5 |
| B3 | 金额专用排印 | tabular-nums、千分位、小数弱化、货币符号弱化 |
| B4 | 双文字体栈 | Latin + CJK 分别指定；数字单独字族 |
| B5 | 截断策略 | 标题 1 行省略；关键数字不省略 |

### C. 色彩
| # | 规范 | 落地要求 |
| --- | --- | --- |
| C1 | 语义优先 | 语义色跨主题恒等（INV-1：红=收入） |
| C2 | 色彩即状态 | 状态必须有颜色以外冗余 |
| C3 | 对比度 | 正文 ≥ 4.5:1，大字/图标 ≥ 3:1 |
| C4 | 彩色面积 | 一屏 ≤ 15% |
| C5 | 灰阶纪律 | 中性层 ≥ 4 级 |

### D. 布局与控件几何（必须给出数值）
| # | 规范 | 落地要求 |
| --- | --- | --- |
| D1 | 4 基数间距 | 4/8/12/16/24/32 |
| D2 | 触控目标 | ≥ 44×44（含透明热区）；可点高度优先 ≥ 48 |
| D3 | 对齐成线 | 图标光学中心 / 文字基线 / 小数点成列 |
| D4 | 控件必画状态 | 默认、按下、禁用；选中、焦点、错误、加载按需 |
| D5 | 圆角成档 | 全局 4 档以内，写进令牌 |
| D6 | 控件解剖 | 每个控件写清：宽/高、padding、margin、icon 尺寸、圆角、描边、阴影 |

### E. 图标系统（本轮必须全部重画）
| # | 规范 | 落地要求 |
| --- | --- | --- |
| E1 | 从零绘制 | 禁止继续用 Material Icons / emoji / 汉字图标 |
| E2 | 一套语言 | 统一 24 网格、线重、端点、圆角、光学尺寸 |
| E3 | 交付源文件 | **必须交 SVG**（见 §3 资产清单），不是截图 |
| E4 | 规格写死 | 每枚：24×24 viewBox、stroke-width、stroke-linecap、fill=none、currentColor |
| E5 | 码位映射 | 提供 icons.json：name → svg 路径名 → codepoint 建议 |
| E6 | 状态图标 | 默认/选中/禁用 三态的着色规则写清 |

### F. 反馈与交互（必须写交互规格）
| # | 规范 | 落地要求 |
| --- | --- | --- |
| F1 | 按压反馈 | scale / 叠色 / 描边变化，时长 80–120ms |
| F2 | 六类状态 | 按下、成功、失败、加载、空、离线 |

| F5 | 手势 | 列表滑动删除？长按？下拉刷新？写清有/无 |

### G. 深色模式（不是反色）
| # | 规范 | 落地要求 |
| --- | --- | --- |
| G1 | 独立取色 | 禁止 invert 亮态 |
| G2 | 面重于影 | 暗态用表面明度分层，阴影弱化 |
| G3 | 降饱和提亮 | 品牌色/分类色在暗底调整 |
| G4 | 避免纯黑 | 深灰优先 |
| G5 | 文字非纯白 | #E8EAED 一带 |
| G6 | 亮暗同构 | 同布局同规格，只换令牌 |

### H. 中英双语
| # | 规范 | 落地要求 |
| --- | --- | --- |
| H1 | 真实语料 | 无 lorem、无机翻腔 |
| H2 | 文案膨胀 | 英文长 30–100%，禁止写死宽度 |
| H3 | 日期 | 中 2026年9月29日 / 英 Sep 29, 2026 |
| H4 | 金额 | ¥1,234.56 / $1,234.56，策略统一 |
| H5 | 字体栈 | Latin + CJK + 数字 分别指定 |
| H6 | 布局弹性 | 可省略/截断/换行 |
| H7 | LTR | 用 start/end，不写死 left/right |

## 4 · 开场指令（从这里开始复制）

```text
你是资深产品 UI / 设计系统设计师。工作目录：
C:\Users\lizhenyu\WorkBuddy\Dev\PlainApp
（Flutter 工程在其下的 plain/，本轮你【不要】改 plain/ 里的任何代码。）

【产品】
素记 / Plain —— 本地优先记账 App（Android / iOS / Pad）。
气质：安静、可信、数字优先。不是玩具，不是仪表盘，不是「可爱手账」。
品牌识别色：青瓷 #14B8A6 × 珊瑚 #FF6B6B；默认皮肤「素白」。
必须同时支持：深色 / 浅色；中文 / 英文。

【本轮任务 —— 设计系统全量交付】
不是「画几张好看的图」，而是交付一套【编码侧可直接实现】的设计系统：
资源（图标 SVG）+ 令牌 + 排版规格 + 控件解剖与状态 + 交互规格 + 8 屏高保真。
只做设计，不写 Flutter / Dart，不动 plain/lib。

【你必须理解的交付观】
UI ≠ 配色 + 效果图。UI = 
  资源（图标/插画） 
  + 数值（字号字重行高、间距圆角、控件尺寸、触控区）
  + 状态（按下/禁用/选中/焦点/加载/错误/空）
  + 交互（按压反馈、转场、手势、焦点环）
  + 布局（区块顺序、对齐、留白节奏）
  + 内容（中英文案、日期、金额）
少任何一层，编码侧就只能猜。

【为什么重做 —— 你要避开的失败】
上一版「暖纸 + 楷体 + 柔光」方向已被否决，截图在 redesign/screens/。
失败点（做完前打开对照，禁止再犯）：

1. 米黄叠米黄、发灰发闷，像 AI 理财模板，没有品牌记忆点。
2. 标题用楷体/书法体 —— 廉价、过时、和数字界面不搭。
3. 到处「淡彩圆角方块托图标」：贴纸感，模板脸。
4. 首页结余卡角上的柔光渐变是污渍。
5. 数字键盘没有键帽结构，数字漂在空白上，像没做完。
6. 纯黑 FAB / 纯黑开关砸在软米色上，又重又脏。
7. 层级弱：该突出的不够狠，该退的不够安静。
8. 无意义徽章 chip 混进列表。
9. 没有独立暗态设计。
10. 没有英文长度校核。
11. 图标是拼凑的，不是一套系统。
12. 控件没有尺寸/触控区/状态规格 —— 编码只能猜。

一句话：上一版输在「没品味 + 没规格」。这一版要「有克制的锋利 + 可编码的完整」。

【视觉方向 —— 安静的账本 Quiet Ledger】
对标克制度与信息密度，不是对标皮：
- Copilot Money / Monarch 的金额排印与卡片呼吸
- Things 3 的留白纪律与图标安静感
- Stripe Dashboard / Linear 的中性层与「一屏一个重点」
不要对标：可爱手账、小红书、Material 默认主题、暖色滤镜 App。

定调四条：
1. 中性层干净不要暖：亮态近真白/冷白灰；暗态近真暗灰；≥4 级灰阶。
2. 数字是唯一主角：金额排印是全 App 记忆点。
3. 结构靠线与留白，不靠盒子：少行行卡片；圆角 4 档以内。
4. 色彩是语义不是装饰：一屏彩色面积 ≤ 15%。

【UI 设计规范 A–H】（逐条遵守）
A 信息层级：一屏一重点；四手段建层级；读序可预测；组间>组内。
B 排版：字阶 6–8 级封闭；中文行高 1.5–1.7、西文 1.3–1.5；
   金额 tabular-nums/千分位/小数弱化；Latin+CJK+数字分栈；截断策略写清。
C 色彩：语义恒等；状态不只靠色；对比度正文≥4.5:1、大字图标≥3:1；
   彩色面积≤15%；灰阶≥4 级。
D 布局几何：间距 4 基数；触控≥44×44；对齐成线；状态必画；圆角成档；
   控件必须有解剖尺寸表。
E 图标：本轮全部重画；一套语言；必须交 SVG 源；规格写死；码位映射。
F 反馈交互：按压反馈 80–120ms；六类状态；转场写明；危险操作形态分离；
   手势有/无写清。
G 深色：独立取色禁止反色；面重于影；降饱和提亮；避免纯黑；文字非纯白；亮暗同构。
H 中英：真实语料；英文膨胀 30–100%；日期金额双格式；字体分栈；布局弹性；LTR/start-end。

【硬禁令】（违反即返工）
- 禁楷体/书法体/手写体做 UI 文案。
- 禁整屏暖米黄、奶茶色、脏粉、咖啡色暗底。
- 禁柔光球/渐变污渍/大面积模糊光晕当装饰。
- 禁每个列表行都套淡彩圆角图标底板。
- 禁无结构漂浮控件。
- 禁纯黑大块怼浅色底，也禁浅色块粗暴怼纯黑底。
- 禁无意义徽章、emoji 图标、汉字图标、Material 默认皮。
- 禁亮态做完「改改就当暗态」。
- 禁只按中文长度排版。
- 禁只交「方向说明」不交图标 SVG 与控件规格表。
- 禁继续使用 Material Icons 或现有 PlainIcons 造型。
- 禁为了氛围牺牲对比度。

【必须保留的产品约束】
- 48 字段 AppTokens：字段名不改，可改值/可建议增补（写入 meta.additions）。
- 10 主题 × 亮暗 = 20 组合可解析。
- 语义色与 12 分类基色跨主题恒等（INV-1）；分类 ink 态可重做。
- 间距 4 基数；触控 ≥ 44×44。
- 字号三档（标准/大/特大）。
- 深色+浅色；中文+英文。
- 金额 int64「分」语义在设计上体现为：永不显示精度噪音，小数弱化。
```
