## 1. 设计定稿

图标由两层构成：**暖米黄底 `#F4EAD8`** ＋ **存钱罐小猪** ＋ 其下方**「素记」字标**。

- **主图形**取自 App「我的」页品牌展示块的 `Icons.savings_outlined`（Material 图标，码位 `U+F336`），橙金色描边。存钱罐直接对应"记账"语义，且描边造型在 24dp 时就不会糊，无需自造图形。
- **字标**用的是思源宋体 Heavy 的「素记」二字，与主图形同置于图标内。
- 底色取自 App 内该展示块的实际渲染色（含透明度合成后的结果）；主图形与字标色在其基础上**按图标场景重新定标**（见 §1.1、§1.2），不在图标内照搬 App 内明度。

### 1.1 一处必要偏离：小猪明度被压深

App 内小猪用的是主色 `#DDA23C`，在米黄底上对比仅 **1.91:1**，桌面上几乎看不见。定稿压深为 `#A66A0C`，对比升至 **3.74:1**（≥ WCAG 图形类阈值 3.0）。

这不是风格偏好。**「App 内的装饰块」与「桌面图标」是两个不同的显示场景**：前者面积小、四周有留白、用户是主动进入该页面查看；后者要与壁纸抢注意力、且用户的视线是扫过的。同一组配色从前者搬到后者，必须提升对比。

品牌一致性靠**色相**维持（同为暖黄金），不能靠明度——照搬明度就得到一枚看不见的图标。

| 用途 | 色值 | 对比（对底 `#F4EAD8`） |
|---|---|---|
| App 内主色（杏黄） | `#DDA23C` | 1.91:1 ✗ |
| **图标小猪** | `#A66A0C` | **3.74:1** ✓ |
| **图标字标** | `#7A4A0E` | **6.26:1** ✓ |
| 图标底 | `#F4EAD8` | — |

### 1.2 字标为何用同族深金（v2.1 修订）

v2.0 的字标是中性近黑 `#332F28`（11.16:1），理由是"小尺寸耐衰减"。实际观感被否——**突兀**。

诊断结论：**问题不在"黑"，在于把中性近黑与高饱和金并置**。

1. **色相断裂。** 猪的饱和度 87%、色相 37°，字标 `#332F28` 饱和度仅 12°像素级的中性色。同一画面里"高饱和暖彩 + 近中性黑"读作两套色彩系统。
2. **层级反转。** 字标 11.16:1，主图形 3.74:1——**字比符号更重**。App 图标里符号应是主视觉，字标是从属。

改为**同族深金 `#7A4A0E`**：色相 33°（与猪 37° 同族）、**保留 79% 饱和度**，读作"深金"而非"黑"；对比 6.26:1，高于正文阈值 4.5:1，又弱于主图形，层级归位。

由此形成**同色三阶**：`#DDA23C`（App 内品牌色）→ `#A66A0C`（图标主图形）→ `#7A4A0E`（字标）。

**注意区分**：备选2 的字标保持墨色不变。那套方案里**猪与字同为墨色**，是自洽的水墨体系，不存在"混搭"问题——突兀感的来源是**混搭**，不是墨色本身。

### 1.3 字体的授权区分

| 元素 | 字体 | 授权 |
|---|---|---|
| 小猪 | Material Icons | **Apache License 2.0**，商用免费、可修改、可再分发 |
| 「素记」 | 思源宋体 Heavy（Source Han Serif SC） | **SIL OFL 1.1**，商用免费、可嵌入 |

**禁止改用系统字体（微软雅黑、中易宋体等）作为字标。** 这类字体随 Windows 分发，其 EULA 限制将字形用于商标/标识；界面渲染用系统中文字体不受此限。这是"界面字体"与"图标素材"的授权差异，容易在上架前才被发现，届时全套返工。

### 1.4 关键参数

| 参数 | 取值 | 说明 |
|---|---|---|
| 底色 | `#F4EAD8` 纯色 | 不做渐变：图标仅 3 图层，纯色使 adaptive 背景层无需为裁切做补偿 |
| 小猪宽 | 画布 50.0%（无字标时 60.0%） | 描边宽度随墨迹等比缩放，24dp 下仍约 2px |
| 字标高 | 画布 13.2% | "小字"定位，弱于猪但留可辨 |
| 字距 | 字号的 10% | 宋体方块字，过宽则散、过窄则挤 |
| 猪—字间距 | 画布 4.8% | 按墨迹包围盒计算，非按 em 框 |
| 整体中心 | 画布 48.7% | 略高于几何中心，补偿下方字标的视觉重量 |
| 圆角 | **不加** | 系统与各家 ROM 会自行裁切，自带圆角会叠成双圆角 |

### 1.5 四方案评审

四套候选及其逐图评审见 `图标方案/`（`00-四方案总览.png` ＋ 四个子目录，每个含主图、尺寸阶梯、桌面实况、平台形态，以及 3 形状 × 11 尺寸的 `plain_logo_*.png` 素材）。

| 方案 | 底 | 主图形 | 字标 | 猪/底 | 字/底 | 判断 |
|---|---|---|---|---|---|---|
| **定稿** | `#F4EAD8` | `#A66A0C` | `#7A4A0E` | 3.76:1 | 6.26:1 | **推荐落地**。同色三阶，层级正确 |
| 变体 | `#F4EAD8` | `#A66A0C` | `#A66A0C` | 3.76:1 | 3.76:1 | 最"成套"，但字标比主图形更弱，不推荐 |
| 备选1 | `#976411` | `#FFF8EC` | `#FFF8EC` | 4.80:1 | 4.80:1 | 货架识别最快；满色底显重，与 App 内米白底不一致 |
| 备选2 | `#F4EAD8` | `#332F28` | `#332F28` | 11.16:1 | 11.16:1 | 水墨自洽、对比最高；但丢失存钱罐的"金"意象 |

备选1 的底色在 v2.1 由 `#B87A15` 压深为 `#976411`——原值下米白字仅 **3.41:1**，低于正文阈值，属不合格配色。

## 2. 小尺寸字标策略

**字标在 48px 下仅约 6px 高，物理上无法辨认，只会退化成一道灰痕。** 故按下表分级：

| 资源 | 是否带字标 | 原因 |
|---|---|---|
| Android mdpi 48px / hdpi 72px | ✗ | 无字标，小猪放大至 60% 填住构图 |
| Android xhdpi 96px 及以上 | ✓ | |
| iOS 20 / 29 / 40 / 58 / 60 / 76 / 80 / 87 px | ✗ | 设置页、Spotlight、通知等处 |
| iOS 120 / 152 / 167 / 180 / 1024 px | ✓ | 主屏图标与大图 |
| macOS 16 / 32 / 64 px | ✗ | |
| macOS 128 px 及以上 | ✓ | |
| web favicon 32px | ✗ | 固定无字标，小猪放大至 66% |

阈值写在 `icon_design.py` 的 `SMALL_PX = 96`，改一处即全局生效。

**一个实际观感提示**：主流 Android 设备多为 xxhdpi/xxxhdpi，系统会取 144/192px 资源缩放到 48dp 显示，因此**真机上看到的是带字标版本**，字标约占图标高度 13%。这在小猪与字标的比例上成立，但不属于"放大后仍清晰"的量级；桌面本身也会在图标下方显示应用名，字标在此属强化而非必需。若希望统一去掉字标，把 `WORDMARK` 置 `False` 即可重生成全套。

### 3.1 工程侧配套改动（v1.0 已落地，v2.0 沿用）

| 文件 | 改动 | 原因 |
|---|---|---|
| `android/app/src/main/AndroidManifest.xml` | `android:roundIcon="@mipmap/ic_launcher_round"` | 原缺失，Android 7.1+ 圆形启动器取不到圆形图标 |

`theme_color` 保持品牌识别色 `#14B8A6`（青瓷主色，见 `theme_registry.dart`）而非图标底色——它是浏览器 UI（地址栏等）的着色，跟随品牌主色，与图标底无绑定关系。

## 4. 平台差异：为什么必须分别渲染

同一张图复用到所有位置是常见错误。三处硬约束：

**iOS 不接受 alpha 通道。** 图标必须是满幅方形、不透明的 RGB；圆角由系统裁切。带 alpha 的图会在 App Store 提交时被拒。

**Android 自适应图标有安全区。** 画布 108dp 中只有中间 72dp 保证可见，外围 18dp 用于各家 ROM 的遮罩形状与视差动画。前景内容必须缩至 66.7% 居中，否则会被裁。本文实现让内容占可见区与 iOS 观感对齐（因前景缩放恰为可见区比例，两侧内容比例取同一值即可）。

**圆形启动器需要内容再缩。** `ic_launcher_round` 的内容缩至 90%，给圆形边界留余量。实测各密度下内容最大半径均小于画布半径（48px 档 23.8 / 24.0）。

此外，Android 传统图标**不加圆角**——系统或 ROM 可能二次裁切，自带圆角会出现双重圆角。

## 5. 生成与验证

设计定稿在 `.workbuddy/tools/suji-icon/icon_design.py`，全部参数集中在文件头部。

```bash
# 预览生成计划（不写文件）
python generate.py --dry

# 备份现有图标 -> 生成全部资源 -> 复核尺寸与通道
python generate.py

# 生成四方案评审包 -> PlainApp/图标方案/
python make_schemes.py

# 生成 logo 素材（4 方案 × 3 形状 × 11 尺寸 = 132 个 plain_logo_*.png）
python make_logo_assets.py

# 自检：配色方案对比、尺寸阶梯、前景安全区、圆形遮罩、对比度
python preview_check.py

# 从磁盘回验：尺寸、alpha、安全区、圆形遮罩、adaptive 合成
python verify.py

# 桌面实况：深浅壁纸 × 尺寸阶梯 × 密度梯度 × 7 种 ROM 遮罩
python desktop_sim.py
```

`generate.py` 会自动把被覆盖的旧文件备份到 `.workbuddy/backup/icons-original-<时间戳>/`。

`verify.py` 检查的不是"文件有没有生成"，而是四类实质问题：尺寸与通道是否符合平台要求、前景是否落在安全区内、圆形遮罩下内容是否越界、自适应前后景合成后是否正常。`preview_check.py` 另出配色方案对比与对比度数值。

## 6. 注意事项

**改设计后不要手改 PNG。** 所有尺寸都由脚本从矢量式参数渲染（超采样 8×/4×/2× 后 LANCZOS 降采样），手改单张会导致各档不一致。改 `icon_design.py` 头部常量后重跑 `generate.py` 即可全套更新。
