## Logo 素材：命名与规格

命名格式 `plain_logo_<形状>_<宽>x<高>.png`：

```
plain_logo_square_24x24.png     直角
plain_logo_rounded_24x24.png    圆角
plain_logo_circle_24x24.png     圆形
```

| 形状 | 说明 | 四角 |
|---|---|---|
| `square` 直角 | 满幅方形、不透明，无任何圆角 | 不透明 |
| `rounded` 圆角 | 圆角半径 = 边长的 **22.37%**（iOS / macOS 图标标准） | 透明 |
| `circle` 圆形 | 正圆遮罩 | 透明 |

尺寸档位共 **11 档**：
`16 · 24 · 32 · 48 · 64 · 96 · 128 · 192 · 256 · 512 · 1024`

字标规则同 App 图标：**资源 < 96px 省略「素记」**，并把小猪放大到 60%（48px 下字标仅约 6px 高，物理不可辨）。故 16 / 24 / 32 / 48 / 64 为纯图形，96 及以上带字标。

### 三形状的内容尺寸**不同**——这是刻意的

圆面积只有方形的 **78.5%**（π/4）。内容原样搬进圆形会显小、显飘。故按面积等效放大：

| 形状 | 缩放 | 依据 |
|---|---|---|
| 直角 | ×1.000 | — |
| 圆角 | ×1.022 | 圆角只吃掉 4.3% 面积 |
| 圆形 | ×1.128 | 1/√(π/4) |

这与 iOS / Android 的处理同源——adaptive 前景缩到 66.7%、`ic_launcher_round` 缩到 90%，都说明"同一份图套不同遮罩"不是正确做法。对照实测图见 `.workbuddy/tools/suji-icon/preview/shape_scale_study.png`。

选定方案后执行 `generate.py`，另可产出全部 49 个工程图标资源（Android 5 档 ×4、iOS 15 档、macOS 7 档、Web 5 个）。

## 透明底两版

上述 132 个素材均为**满幅不透明底**——它们服务"桌面图标"场景，靠底色与壁纸争注意力。另一类场景需要**四周透明**的 Logo：App 内品牌位、启动页、关于页、深浅主题切换、对外物料直接摆放。为此另出两版：

| 版本 | 目录 | 主图形（猪） | 字标 | 在 `#F4EAD8` | 在 `#121212` |
|---|---|---|---|---|---|
| 透明底 · 浅色/通用 | `定稿-透明底/` | `#A66A0C` | `#7A4A0E` | 3.76 / 6.26:1 | — |
| 透明底 · 深色主题 | `定稿-透明底-深色/` | `#DDA23C` | `#F4EAD8` | — | 8.30 / 15.71:1 |

命名：`plain_logo_transparent_<px>x<px>.png` / `plain_logo_transparent_dark_<px>x<px>.png`，各 11 档尺寸。

四条设计约束：

1. **深色版直接用两个品牌原色**——主图形取 App 内品牌金 `#DDA23C`，字标取品牌米 `#F4EAD8`。在 `#121212` 上为 8.30:1 与 15.71:1，比值 **1.89**，与浅色定稿的 6.26 / 3.76 = **1.67** 同阶：**层级关系（符号为主、字标从属）无损迁移**。
   不采用"整枚反白"：那会丢掉存钱罐的"金"意象，与 备选2 同一处取舍。
   注意 8.30:1 高于浅色版的 3.76:1 不是失误——薄笔画的字标在深底上需要的对比度天然更高，这是**方向反转**而非破坏层级。
2. **只有 11 档尺寸，没有 square / rounded / circle 三形状**。三形状的差别**只在底板遮罩**（直角 / 22.37% 圆角 / 正圆），底板透明后遮罩无从作用，输出逐像素相同。圆形的 ×1.128 面积补偿同理不适用——补偿是为"内容放进圆内显小"服务的，自由摆放的素材不存在这个前提。
3. **不得由现有不透明 PNG 抠底**。抗锯齿边缘的半透明像素是"米色 × 墨色"的混合值，反解会得到一圈灰环。正确做法是重渲染（`content_layer` 去掉底板）。
4. **内容与定稿 100% 同源**：复用 `icon_design.content_layer` 的全部常量（`PIG_W` / `TXT_H` / `TRACK` / `GAP` / `CENTER_Y` / `SMALL_PX`）。1024 版墨迹边界 `x 298–725 / y 203–793`，与 `定稿/plain_logo_square_1024x1024.png` 完全重合。`< 96px` 同样隐藏字标、小猪放大到 0.60。

生成脚本另有一处必须保留的实现细节：Pillow 10.4 的 `resize` 对 RGBA 走"预乘 → 重采样 → 反预乘"，低 alpha 像素会被放大出噪声 RGB。故脚本里 alpha 走 LANCZOS 重采样，**RGB 逐像素判定归属后直接取品牌原色**，杜绝任何中间色（回验项之一：`alpha > 0` 的像素 RGB 必须严格 ∈ {品牌金, 品牌米}）。

单版校验图见 `.workbuddy/tools/suji-icon/preview/transparent_transparent_check.png`（浅色版）与 `transparent_transparent_dark_check.png`（深色版）。

## 为什么「金 + 黑」显得突兀

**根因不是"黑"，是混搭。** 三点：

1. **色相断裂** —— 金猪饱和度 87%，字标 `#332F28` 饱和度仅 12%。高饱和暖彩与近中性黑并置，读作两套色彩系统。
2. **层级反转** —— 字标 11.16:1 比主图形 3.74:1 更"重"。App 图标里**符号应为主视觉**，字标是从属。
3. **权重错配** —— 对比度并非越高越好。字标作为从属元素，落在 **5.5–7.5:1** 才是正确档位。

改法：字标改用**同族深金 `#7A4A0E`** —— 色相 33°（与猪 37° 同族）、保留 79% 饱和度，读作"深金"而非"黑"；对比 6.26:1，既高于正文阈值，又弱于主图形。

由此形成**同色三阶**：

```
#DDA23C  →  #A66A0C  →  #7A4A0E
App 内品牌色    图标主图形     字标
```

**特例说明**：备选2 保持全墨，不属此问题——那套方案里猪与字同为墨色，是自洽的水墨体系，不存在混搭。

## 复跑

```bash
cd .workbuddy/tools/suji-icon
python make_schemes.py              # 重出四方案预览（00-总览 + 各目录 01–04）
python make_logo_assets.py          # 重出 logo 素材（4×3×11 = 132 个 plain_logo_*.png）
python make_transparent_assets.py   # 重出透明底两版（2×11 = 22 个 + 01-总览）
python generate.py                  # 按当前 icon_design.py 重出工程图标资源
python preview_check.py             # 对比度 / 安全区自检
python verify.py                    # 从磁盘回验工程资源
```

设计参数集中在 `icon_design.py` 文件头部；改色只动 `BG` / `PIG_C` / `TXT_C` 三行。
改形状代号（中文）、增删尺寸档位、改圆角半径，分别改 `make_logo_assets.py` 的 `SHAPES` / `SIZES` / `RADIUS_REL` 后重跑。
透明底两版的配色与底色在 `make_transparent_assets.py` 的 `VARIANTS` 里，改色只动 `pig` / `txt` 两处。
