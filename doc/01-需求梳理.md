## 一、产品定位与目标

一款面向个人与家庭的多端记账应用，核心价值主张是「3 秒记一笔，看得懂钱花在哪」。免费层提供不打折的核心记账体验（对标钱迹的免费心智），付费层围绕效率（自动导入、OCR、周期记账）、数据资产（多端云同步、备份、导出）、深度分析（多账本、资产、报表）与 AI 能力（无感记账、消费洞察）四条线变现。长期定位是个人财务数据中枢。

**成功指标（上线 12 个月）**：次日留存 ≥ 40%，30 日留存 ≥ 20%；月活跃记账天数 ≥ 15 天的用户占比 ≥ 35%；付费转化率 ≥ 3%；人均日记账笔数 ≥ 3（咔皮做到了 6 笔，是 AI 无感记账的天花板参照，我们以 3 为健康线）。

**版本目标（v0.7 修订）**：商业化整体后移至 V4.0（原 V2.0 商业化结构整体顺延）。V2.0 与 V3.0 的目标转为「把免费体验做到无可挑剔，把付费理由做厚」——商业化的说服力来自产品深度而非付费墙位置。因此本版新增的 V2.0/V3.0 需求，全部按「免费可用的深度功能」设计，付费点仍只有云同步与 AI Pro 两条主干。

## 二、用户画像与核心场景

**P1 效率型个人记账者（主力，约 52%）**。25–35 岁职场人群，每天 3–8 笔收支，痛点是「懒得记、忘了记」。核心诉求：3 秒记一笔、周期账单自动生成、月底看分类占比。付费意愿集中在效率功能。新增洞察：咔皮验证了这批人愿为「无感记账」（截图/语音识别）付出极高使用粘性。

**P2 管理型家庭用户（约 28%，付费主力）**。30–45 岁，双人或多人协作记账，房贷、育儿、通勤等固定支出结构。诉求：家庭账本、成员权限、分类预算与超支提醒、信用卡账单日、年度复盘。对多端同步与数据不丢有刚性要求。

**P3 极客 / 隐私敏感型用户（约 10%，口碑放大器）**。酷安、GitHub 活跃人群。诉求：本地存储、开放格式导出、WebDAV 自建同步、不强制注册。付费意愿一般，但评分、社区传播与编辑推荐贡献极大。

**P4 情绪价值型年轻用户（约 5%，增长变量）**。Z 世代，记账动因是「月光焦虑」与自我探索（消费人格、攒钱打卡）。诉求：可爱视觉、鼓励式反馈、社交货币型年度报告。对咔皮的「该攒攒该花花」人设和 Omi 的虚拟角色付费验证了该人群存在。付费点：限定主题皮肤、角色、AI 人格报告。

**P5 资产管理型用户（v0.7 新增，约 5%，V3.0 目标人群）**。30–45 岁，有房贷/车贷、持有基金股票、关注净值变化。诉求：投资持仓与净值追踪、贷款摊销与提前还款测算、资产折旧。付费意愿强（愿为「看清自己有多少钱」付费），是 V3.0 从记账工具升级为「个人财务中枢」的人群基础。当前产品以「投资账户」占位但无持仓，净值数字不可信——这是 V3.0 的核心修复项。

### 3.2 钱迹：极简体验与信任资产的教科书

**定价实况（v0.3 修正）**：¥6/月、¥36/年、¥128 终身买断，会员全平台通用；3000 万下载、600 万用户；iOS 4.9 分（2.2 万评分）；鸿蒙版 2024-09 上线。

可借鉴优点，逐条映射：
1. **「三无」承诺（无广告/无开屏/无理财）**——不是功能而是品牌资产，转化为商店描述的信任状。映射：M8.3 产品宪法，另加「绿色应用公约」类第三方认证作为 V1.x 信任背书动作。
2. **快速记账的实现精髓（v1.x 修订）**：键盘极简（数字/小数点/退格/OK），点分类只预选，**OK 一次确认落库**。映射：F1.1 的核心交互规格（见 5.1 节）。
3. **免费导入所有主流竞品数据 + 筛选结果免费导出 CSV**——数据进出的双向自由是「数据是你的」承诺的实证。映射：F7.5 导入免费（获客武器）；筛选结果导出（CSV）免费，导出中心的 Excel/PDF 成品导出收费（F7.6，V3.0 交付、V4.0 起随付费墙收费），对价是云同步——这个差异必须在商店描述里主动说清楚，否则会被拿来攻击。
4. **AI 自动记账（4.3.0 起，识别支付宝/微信账单）**——钱迹证明无感记账已是头部标配，不做会被判「功能落后」。映射：F10.1 截图记账进主线（V2.0 而非 V3.0）。
5. **独立开发者人设**（唐昱春一人身兼开发/产品/运营/客服）——社区情感加成。我们不具备也不硬凹，改为「小团队 + 公开路线图 + 用户共创频道」的透明化运营。
6. **秒开模式**——冷启动体感是记账 App 的第一印象生死线。映射：非功能指标冷启动 ≤ 2s 加严为 ≤ 1.5s（中端 Android）。
7. **信用卡账单周期管理**（v0.7 新增）——账单日 / 还款日 / 免息期自动计算，防逾期防罚息。映射：F2.5（V2.0）。

### 3.3 咔皮记账（商汤）：AI 无感记账 + 情绪价值的降维打击

6 个月破百万用户、人均日记账 6 笔（品类天花板）、AI 记账赛道 Top 1。这是当前对传统手动记账产品威胁最大的玩家，其打法必须拆解：

1. **无感记账三件套**：支付后截图（iOS 快捷指令挂控制中心，App 都不用打开）、语音/文本一句话（「早餐 18」）、Android 无障碍自动记录。映射：F10.1 全量纳入，但免费额度制（10 次/月）而非全免费——咔皮背靠商汤烧得起模型成本，我们不能。
2. **AI 消费周报的主动触达**——不是用户来看报表，是 AI 推给你「本周购物占 47%，比上周克制多了」。这是 AI Agent 式的主动唤回，比推送通知的打开率高一个量级。映射：F10.2 周报作为留存引擎，简版免费。
3. **情绪价值设计**：鼓励式点评、消费人格、攒钱成就（「本周省下 210 元，离五位数存款更近了」）。注意其翻车教训：点评翻车引发「被内涵」吐槽，最终加了关闭开关。映射：F10.4 人格报告设计三原则——只夸不贬、可关闭、阈值触发（大额支出才调侃）。
4. **「注册送一年会员 + 每日记账 +1 天」的留存钩子**——把会员时长与使用习惯绑定。映射：改造为「记账契约」（见 10.5），里程碑式而非每日式，成本更可控。
5. **主动式提醒体系**（v0.7 新增）——预算临近预警、会员订阅免费期结束前提醒取消、信用卡还款日前提醒三合一，是咔皮的核心留存点。映射：F6.7 提醒中心（V2.0）。
6. **情绪价值高频化**（v0.7 新增）——咔皮的情绪反馈是日常化、高频、轻量的（每次记账、每周报告），而非年度一次。映射：F9.5 情绪反馈（V2.0）与 F10.2 合并设计。
7. **其软肋即我们的机会**：AI 误判（「昨天」解析错日期）需手动修正、大厂产品无本地优先/导出自由、商业化未定（免费是烧钱态不可持续）。我们的对位：确定性体验（手动 3 秒记账永远可靠）+ 数据自由 + 明码标价。

### 3.4 Omi 记账：情绪价值的付费验证

App 收入数据平台的真实结构：**一次性买断占收入 85%、年订阅 15%**；中国区主力 SKU 为年订阅（7 天试用）与终身买断。三条可抄的作业：
1. **Starter Pack 低门槛首购**（$2.99 档：入门包）——付费漏斗的第一级台阶，把「从未付费」变成「付过 6 块钱」，后续订阅转化率数倍提升。映射：L3 点购层（见 10.4）。
2. **虚拟角色人设**（小仓鼠财务管家、可选霸道总裁/阳光男友人格）——P4 人群愿为陪伴感掏钱。映射：F9.4 记账伙伴系统（角色 + 主题打包点购）。
3. **买断收入占 85% 的现实**——国内情绪价值型产品的付费主力仍是买断。映射：定价策略中买断档位必须保留且给足权重（修正 v0.2「订阅为主」的倾斜，改为双轨并重）。

### 3.5 随手记 / 海外系的可取点

随手记：**100+ 场景账本模板**（装修、育儿、生意）降低多账本的使用门槛。映射：F3.1 交付 8 个精模板而非空白账本。另**报销工作流**（差旅报销）是国内少有的 toB 切入设计——映射：F1.9 报销工作流（V2.0）。

PocketGuard：**订阅浪费检测**（「$9.99/月的音乐订阅 3 个月没用了，取消可省 ¥1000/年」）——基于用户自己数据的省钱发现，付费说服力极强。映射：F10.3。另其 **「Leftover / 安全可花」单值**设计（从可用余额中减去账单、目标、刚需，实时给出「今天可以放心花」的数字）是极简决策的典范——映射：F5.4（V2.0）。

Simplifi：**现金流预测**（基于周期规则预测未来 30 天余额曲线，提前暴露赤字日）。映射：F10.5。另**异常支出监测**（unusual spending watchlist）——映射：F6.7 提醒中心。

Cashew：交易类型驱动 UI（借出/订阅/定期各自不同的界面语义）。映射：F1.4。另**Custom Titles 商户自动归类**（同名称交易自动归入特定分类）实现成本极低而效果立竿见影——映射：F1.7（V2.0）。

### 3.6 开源体系的深度借鉴（v0.7 新增）

**Actual Budget（~24–28k★，TypeScript/SQLite，MIT）**——规则引擎是本赛道技术标杆，设计为「条件（IF）+ 动作（THEN）+ 执行阶段（pre/post）+ 优先级排名 + 模板化动作」，并支持规则变更前预览影响面。另有 **Age of Money（资金年龄）** 独立指标（量化「赚到的钱平均多久后才花掉」）与**对账模式（Reconciling）**。映射：F6.8 规则引擎（V2.0，直接对标完整设计）、F4.8 资金年龄（V3.0）、F2.6 对账模式（V2.0）。

**Firefly III（~24.8k★，PHP，AGPL-3.0）**——复式记账、**Piggy Banks 储蓄罐**（把储蓄账户拆成带目标与截止日的虚拟子账户）、REST API + OAuth2 + Webhook、多币种并存、camt.053 导入。映射：F5.5 沉淀基金（V2.0，即 Piggy Bank 的中文落地）、F7.9 开放 API（V3.0）、F6.3 导入扩展格式（V3.0）。

**Monarch Money**——**Sankey 桑基现金流图**（Monarch Plus 独有，「收入 → 各支出类别」流向一图看清）、**Goals 3.0**（把「储蓄目标」与「还债目标」明确分离，各带专属逻辑如房贷利息节省计算）、**家庭协作**（无限成员、各自登录、**交易标记 Mine/Theirs/Ours**、**交易级评论**、只读分享给财务顾问）。映射：F4.6 Sankey（V3.0）、F5.6 目标体系（V2.0）、F3.3 家庭协作细化（V3.0）。

**Copilot Money**——ML 自动分类（>90% 准确率，随修正持续学习）、**Amazon 订单级匹配**（一笔「Amazon $87.32」拆解为具体商品行项）、Apple 生态深度集成。映射：F1.7 商户自动学习（V2.0）、F9.3 Apple 生态深化（V2.0）。

**MoneyManager Ex**——**资产折旧/增值率**（每项资产可按年折旧或增值，适配房产车辆）。映射：F2.7 资产折旧（V3.0）。

**YNAB**——**四法则方法论**（给每一块钱一份工作 / 接纳真实支出 / 超支调整不焦虑 / 让钱变老）、**Loan Payoff Planner**（额外还款能省多少利息与多少时间）、**Envelope 信封预算**。映射：F5.7 预算方法论切换（V3.0）、F5.8 贷款摊销与提前还款测算（V3.0）、F5.5 沉淀基金。

**BeeCount（TNT-Likely，Flutter）**：本地优先 + 自建云 + iCloud/WebDAV/S3 多通道同步 + AI capture + **MCP 接口让 LLM 直接操作账本**。印证「可插拔同步通道」架构与本产品双轨同步的契合；MCP 是 2026 年新兴方向。映射：F7.9 开放 API 与 MCP（V3.0）。

**XPENC（Flutter/Drift，小众）**——**银行短信自动捕获**（Android 端监听银行短信自动记账）。国内无 Plaid/GoCardless 类聚合器可用，短信捕获是**不依赖第三方的自动记账可行路径**。映射：F6.9 短信自动记账（V3.0，须过合规评估）。

**Cashew（jameskokoska，4.5k★，Flutter + Drift + Firebase）**：预算自定义周期、类型化交易、多币种双显示、Material You。入选 Google Play「New Apps We Love」（2023-11）——证明小体量 Flutter 产品能拿编辑推荐。

**Fingrom（lyskouski）/ Sossoldi（RIP-Comm，~1.4k★）**：平台无关分层，多端共享业务逻辑层的参考；Sossoldi 以「净值追踪为核心」的产品叙事值得借用——「记账是为了知道我有多少钱」比「记账是为了知道钱花在哪」更接近 P5 人群的心智。

**Wallos（~7.1k★）**：纯订阅追踪器的垂直深度（可视化周期支出、订阅管理），证明单点做深也能获取高关注度。

## 四、开源与竞品缺失清单（v0.2 → v0.7 演进）

**BeeCount（TNT-Likely，2.4k★，Flutter）**：本地优先 + 自建云 + iCloud/WebDAV/S3 多通道同步 + AI capture + MCP。印证「可插拔同步通道」架构与本产品双轨同步的契合。
**Cashew（jameskokoska，4.5k★，Flutter + Drift + Firebase）**：预算自定义周期、类型化交易、多币种双显示、Material You。入选 Google Play「New Apps We Love」（2023-11）——证明小体量 Flutter 产品能拿编辑推荐。
**Fingrom（lyskouski）**：平台无关分层，多端共享业务逻辑层的参考。

**v0.7 调研结论——三个结构性空档**：

1. **交易精度与自动化**（最大空档）。分割交易、规则引擎、商户自动学习三项是国内外中高端产品的共同标配，本产品全缺。国内 App 普遍只有「周期记账」这一种自动化，而规则引擎（导入 500 条账单后自动分类）是「省力度」的质变。来源参照：Actual Budget 规则引擎（pre/post 双阶段 + 优先级 + 模板化动作）。
2. **资产完整性**。本产品有「投资账户」类型却无持仓、有「信用卡」账户却无账单周期、有资产却无折旧 → **净值数字不可信**。补上后「资产总览」才名副其实，这也是 V3.0 人群（P5）的入场券。
3. **主动管家能力**。本产品只有「周期记账」（被动生成），缺「主动推送」——还款日提醒、订阅到期取消提醒、预算分级预警、异常支出提示。咔皮的留存正是靠这套主动体系。

**第四条（结构性机会）**：本产品为 Flutter 工程且已含 `macos/`、`web/` 目录，桌面端与 Web 端边际成本低，而国内 App 普遍缺失——这是差异化窗口，列入 V3.0。

**G-1 「记账月」（Accounting Month）定义**

记账月是**由用户设置的「月起始日」定义的统计周期**：设起始日为 D，则任一日期 T 所属的记账月为「从 T 之前最近的 D 号起，至下一个 D 号前一日止」的区间。默认 D=1，此时记账月 = 自然月。

这是**全产品唯一**的「某笔账单属于哪个月」判定入口，报表、流水分组、预算周期、周期记账、周报/月报、AI 额度重置**一律**以此为准，禁止各处自行按自然月计算。

与自然月的关系：当 D≠1 时二者不同。例如 D=10，则 2026-09-28 属于**记账月 2026-09**（区间 09-10 至 10-09）。凡 UI 需要提示月份归属处，一律使用记账月口径，文案统一为「该账单计入 <记账月>」，不再出现「本月/自然月」这类歧义表述。

**G-2 「是否计入收支」与「来源」的正交口径（解决 C-04）**

「是否计入收支」不是账单自身的属性，而是**由「来源」与「用户标志」共同决定的派生结果**。报表、预算、净资产、消费统计四处一律查下表，不得各处自定义：

| 账单来源 | 计入收支统计 | 计入账户余额 | 进预算统计 | 进消费/分类统计 | 进分类管理「N 笔」计数 |
|---|---|---|---|---|---|
| 手动普通账单 | 是 | 是 | 是 | 是 | 是 |
| 手动·标记「不计入收支」 | 否 | 是 | 否 | 否 | 是（仍是一笔真实账单） |
| 对账调整 | **否** | 是 | 否 | 否 | **否** |
| 转账（含信用卡还款） | 否 | 是（两端） | 否 | 否 | 否（无分类） |
| 借出 / 借入 | 否 | 是 | 否 | 否 | 否（无分类） |
| **贷款还款·本金部分** | **否** | 是 | 否 | 否 | 否 |
| **贷款还款·利息部分** | **是** | 是 | 是 | 是 | 是 |
| 报销垫付（未回款） | 是 | 是 | 是 | 是 | 是 |
| 报销回款 | 否 | 是 | 否 | 否 | 否 |
| 分割交易的父笔 | 是（=父笔金额） | 是（仅父笔计一次） | 否 | 否（分类置空） | **否** |
| 分割交易的子笔 | 否（已在父笔计） | 否 | 是 | 按各自分类计 | 是 |

**核心裁决**：对账调整、转账、借贷、**贷款还款本金**四类均为「内部搬移或余额修正」，**一律不计入收支统计与预算**（贷款还款的**利息部分**属真实资金成本，计入）。这条直接修掉了「每月对账一次就污染一次消费统计」的缺陷。

**G-2.0 分类相关查询的统一过滤（配合 G-2）**

所有「按分类统计/计数/筛选」的查询（报表环形图、分类管理「N 笔」、流水按分类筛选、预算进度、导出按分类）**一律**只取满足「进消费/分类统计 = 是」的账单。**对账调整账单的分类恒为「其他」，但不得计入分类管理的「其他」计数，也不得在按分类筛选时出现**。

**G-2.1 账户余额的定义（配合 G-2）**

**账户余额 = 期初余额 + Σ(该账户上「计入账户余额 = 是」的账单金额 × 方向)**（支出/转出为负，收入/转入为正）。这是全产品唯一的余额口径，**适用于非信用卡账户**（现金/储蓄卡/投资等），禁止任何页面自行「流水累加」或「另存余额字段」。**信用卡账户是唯一例外**：其「欠款余额」是存储值（可被对账直接修正），由账单入账累加维护，聚合仅用于对账校验（见 F2.5）。**转账是一笔记录带两个账户**（非两条镜像），账户维度查询时符号随账户翻转、两账户合计为 0。

**G-3 通知分级（解决 C-05）**

通知分两级，与「是否弹确认」解耦：

| 级别 | 表现 | 触发条件 |
|---|---|---|
| 静默 | 仅进通知中心，不弹窗、不响铃 | 周期账单免确认入账；后台同步完成；备份完成 |
| 响铃 | 系统通知 + 声音 | 预算跨阈值（80%/100%）；提醒中心到期项；用户主动操作的结果反馈 |

**夜间免打扰**（默认 23:00–07:00，可关）：该时段内所有响铃降级为静默；次日 08:00 汇总一条摘要通知（「昨夜 N 笔已入账」+ 预警摘要），若含预算跨阈值则升级为响铃。

**G-4 「记账月」下的时间边界（配合 G-1）**

所有「今天」判定走注入的 `Clock`（禁裸 `DateTime.now()`）；所有「属于哪个月」判定走 G-1；周期记账的锚定日遇短月顺延至月末；用户手动改系统时间不改变已生成账单的归属，仅影响后续生成。

**G-5 家庭共享与记账伙伴的边界（解决 C-07）**

| 项 | 家庭共享（F3.3） | 记账伙伴（F9.4） |
|---|---|---|
| 本质 | 权限与数据归属系统 | 情绪价值与个性化 |
| 数据 | 共用「成员」表（一个用户在同一账本内即为一个成员） | 不涉及成员数据；角色为设备级装扮 |
| 是否影响账单 | 影响（账单带成员归属、AA 参与人） | 不影响（纯表现层） |
| 归属版本 | V3.0 深化（V2.0 先落基础共享） | V3.0 点购 |

二者**共用「成员」概念但不同图层**：记账伙伴不引入新的身份体系，只在表现层叠加角色与文案。

**G-6 「显式保存」契约（v1.x 修订，原「点分类即保存」取消）**

**所有类型一律「点 OK 保存」**：分类宫格点击只预选，不落库；数字键盘仅数字、小数点、退格/清空与 OK（无四则运算）。以下类型另有专属表单：转账、信用卡还款、借出/借入、分割交易、报销垫付。判定规则：**凡涉及「两个账户」或「多个分类」或「后续生命周期」的记账，必须有确认步骤**——因为这三种情况用户无法通过「点一下」表达完整意图。

UI 侧统一：记账页顶部有类型切换（支出 | 收入 | 转账 | 借出 | 借入），切到后四者时宫格区替换为表单区，并出现「保存」按钮。

**G-7 余额遮蔽（Hidden Balance）**

「隐藏余额」是全局开关（设置 → 通用）。开启后全 App 所有金额展示位（账户列表/详情、首页净资产、安全可花、对账结果、报表合计、桌面与锁屏小组件、通知内金额）统一打码为 `✱✱✱✱`。**例外**：对账输入框不遮蔽（用户需看到自己输入的数字）。

**「临时显示 5 秒」的统一语义**：① 作用域 = **单点**（仅显示被点击的那一个数字，不解除整页遮蔽）；② 自点击起 5 秒后**自动重新遮蔽**；③ 连续点击**刷新计时**，不叠加；④ **小组件**点击金额**原地临时显示 5 秒**（不跳转）；⑤ 应用锁开启且「锁定时隐藏金额」为开时，**桌面小组件与锁屏组件一律不展示金额**（不提供临时显示入口）。

### M1 记账核心

**F1.1 手动记账（P0/F）——交互规格**：

记账页自下而上四区：①金额显示区（大字号，实时显示表达式与结果）；②四则计算器键盘（+−×÷，支持连续运算，这是竞品普遍只有加减法的代差点）；③分类宫格（默认 8 个高频分类一屏，按「最近使用 × 使用频率」智能排序，长按拖动自定义位置，右下「更多」展开全部分类）；④属性栏（账户 chip、日期、备注、标签）。

核心规则（v1.x 修订）：**点 OK 保存**——键盘仅数字/小数点/退格/OK；点分类只预选；按 OK 落库。保存后 toast 1.5 秒并自动清零金额，带 5 秒「撤销」；停留输入页支持连续记账（设置中可改为保存后退出）。

边界规则：金额上限 99,999,999.99，强制两位小数；日期默认当前时刻，可回溯任意日期，回溯跨记账月时轻提示「该账单计入 <记账月>」（口径见 G-1）；修改账单时进入同一页面但需显式保存（区分新建与编辑的心智）；撤销手势（保存 toast 上滑撤销，5 秒窗口）。

**输入边界（v0.7 补全，解决 B-01/B-02/B-03/B-04/B-16）**：
- **零值**：金额为 0 时点分类不落库（仅高亮）；但**编辑态**允许保存为 0（保留历史账单的等于 0 的调整），保存时给出「金额为 0」的轻提示。
- **超限**：已达 99,999,999.99 后再输入数字位，忽略该位并触发抖动动画；长按退格为连续删除。
- **除零**：表达式含 `÷0` 时，结果区显示「无法计算」，且此时点分类不落库（提示「表达式有误」）。
- **表达式长度上限**：连续运算符最多 12 个（即 13 个操作数），达上限后忽略新运算符；表达式超长（>14 字符）时字号自适应缩小，最小不低于 18sp。
- **未闭合表达式**：如「25+」点分类，按「25」处理并在 toast 中注明「已按 25 保存」。

验收标准：从启动到完成 ≤ 3 次点击；单笔录入中位数耗时 ≤ 5 秒（埋点度量）；连续记 3 笔不离开输入页。

**F1.2 分类体系（P0/F）**。预置一级 12（餐饮/购物/日用/交通/食材/娱乐/通讯/居住/医疗/学习/人情/其他）+ 二级 41 个。支持新增、编辑（名称、图标、备注）、图标自定义（内置图标库 ≥ 200 + 本地上传）、排序、隐藏、合并（历史账单随迁，禁止孤儿账单）。**每个分类可带一条备注**（选填，≤ 30 字）：分类名限 6 字，说不清「什么算、什么不算」，备注补这个缺口；预置分类自带备注，用户可改。备注属分类权威数据，进备份与云同步，但不参与搜索、筛选与统计。二级分类记忆规则：同名商家（账单备注关键词）二次出现自动带出上次分类——咔皮式的 AI 联想降级为规则实现，零成本。

**分类管理边界（v0.7 补全，解决 C-03 / B-16）**：
- **重名校验**：同一父级下分类名不可重复（含与父级自身重名）；保存时若重名，提示「已有同名分类」并高亮冲突项，不自动改名。
- **隐藏与合并的关系**：隐藏分类**可以作为合并目标**（隐藏只是不显示于宫格，数据完整）；但隐藏分类**不可作为合并来源的默认项被批量选中**。
- **合并的合法性**：仅允许「同层级间合并」。一级分类合并时，其下全部二级分类**整体移动到目标一级分类下**（不做二级合并）；若目标一级分类下已存在同名二级，则该二级合并入同名项（历史账单随迁），并在确认对话框中逐条列出。
- **合并前的预览**：确认对话框必须显示「将影响 N 笔账单，其中 M 笔来自 X 个二级分类」，用户可展开查看明细。
- **合并的来源处置**：原分类**软删除**（进回收站，30 天可撤销），历史账单**同时改写**指向目标分类。撤销合并时，原分类恢复且账单回迁（依赖 change_log 重放，V2.0 起支持）。
- **回收站现状**：回收站**功能产品归属 V2.0，但 V1.0 已全链路实现**（数据层软删除 + `trash_page.dart` UI）。分类合并默认走软删除进回收站，用户可撤销；若未来提供「物理删除」选项，确认文案须注明「合并后不可撤销」。

**F1.3 标签（V2.0，P2/F 单选；多选随筛选能力）**、**F1.4 记账附加属性（P1/F）**（不计入收支、报销标志、成员、手续费/利息/优惠；借出/借入类型使用差异化界面，参照 Cashew；「不计入收支」的口径见 G-2；差异化界面的交互边界见 G-6）、**F1.5 附件（P2/C）**、**F1.6 快捷入口（P0/F）**（1×4 记账小组件、2×2 显示+记账双功能组件、iOS 锁屏/Action Button、Android 磁贴；小组件直达金额键盘，全程不进主界面）。

**F1.5 附件细则（v0.7 补全，解决 C-11 / B-11）**：
- 单笔账单附件上限 **5 张**，单张 ≤ 10MB，仅支持 jpg/png/heic/pdf；超限时提示并可选择压缩（长边压至 2048px）。
- **级联规则**：删除账单时，附件**不立即物理删除**，而是标记为「孤儿附件」，由每日巡检任务清理超过 30 天的孤儿附件；回收站恢复账单时，孤儿附件**随之恢复**（避免恢复后图片丢失）。
- 附件**计入备份**（V2.0 起备份为「数据库 + 附件目录」打包）；附件**不进云同步 V2.0**，V3.0 待评估（图片体量对同步成本影响大）。
- 存储空间不足时，附件上传失败给出「剩余空间不足」并可选择仅保存缩略图。

**F1.7 商户自动学习（P2/F，v0.7 新增）**

商户名（账单备注中的商家关键词，或商家字段）第一次被归入某分类后，第二次出现时自动带出该分类，并在记账页以「上次归入 餐饮-饮料」的可点击提示呈现，用户可一键改。

- 匹配算法：先精确匹配商户名，再退化到前缀匹配（≥4 字重合），均不命中则不联想。**不做模糊 AI 推断**（保持确定性，避免咔皮式误判）。
- 用户修正时**同时更新学习记录**（同一商户给出 ≥2 次不同分类时，以最近 3 次中出现次数最多者为默认，平局取最近一次）。
- 可在设置中一键关闭自动联想；可查看「已学习的商户」列表并逐条删除。
- 与 F1.2 的「二级分类记忆规则」关系：F1.2 是按备注关键词的简单记忆，F1.7 是升级版（含修正学习与冲突裁决）。**V2.0 起 F1.7 取代 F1.2 的记忆规则**，F1.2 该条保留为 V1.0 的临时实现。

来源参照：Cashew「Custom Titles」、Firefly III「Payee 规则」、Copilot「ML 自动分类」。

**F1.8 交易类型化（P2/F，v0.7 新增）**

交易不再只有「收支」一种语义，按类型提供差异化界面：

| 类型 | 界面语义 | 必填差异 |
|---|---|---|
| 普通支出/收入 | 金额键盘（数字/小数点/OK）+ 分类宫格（预选后 OK 保存） | 分类 |
| 转账 | 转出账户 + 转入账户 + 金额（+ 手续费 + 到账金额） | 两个账户 |
| 信用卡还款 | 还款来源账户 + 还款目标卡 + 本期应还 + 实还金额 | 两个账户 |
| 借出/借入 | 对方（往来对象）+ 金额 + 约定还款日 + 利息 | 往来对象 |
| 报销垫付 | 金额 + 分类 + 报销标记 + 报销单号（选填） | 报销标记 |
| 报销回款 | 关联垫付单 + 实收金额 | 关联单 |

- 类型切换在记账页顶部分段控件；切换时**已填金额与日期保留**，分类/账户按类型重置。
- 所有转账类交易在流水页显示为「_双行_」样式（上行为去向、下行为来源），并合计为 0 不计入收支（口径见 G-2）。
- 转账的边界（解决 B-05/B-06）：转出与转入账户**不可相同**（保存时拦截并提示）；转账金额**允许超过转出账户余额**（提示「将导致余额为负」但可继续，符合真实语义）；转出转入币种不同时，须填入两边金额与汇率（V2.0 多币种）。

**F1.9 报销工作流（P2/F，v0.7 新增）**

面向有报销刚需的职场人（也是 toB 方向的第一个触点）：

- 记账时勾选「需报销」，账单进入「待报销」状态，并在金额旁显示橙色标记。
- 「报销」聚合页：按「待报销 / 已提交 / 已回款」三态分组，可按报销单号归集多笔。
- 用户可把多笔垫付**打包成一个报销单**（自动汇总金额、生成明细清单，可导出图片/PDF 用于提交给公司）。
- 收到回款后，记一笔「报销回款」并关联该报销单，系统自动核销对应垫付项；支持**部分回款**（余额保留在待回款）。
- 报销单维度统计：累计垫付、平均回款周期、未回款总额。
- 状态机：待报销 → 已提交 → 部分回款 → 已回款 / 已放弃（放弃不删账单，仅退出报销流程）。
- 付费归属：**免费**。理由：报销是 toB 切入的钩子，且其数据量小、对云同步成本影响低。

来源参照：随手记「差旅报销」、钱迹「报销管理」、Monarch Plus。

### M2 账户与资产

**F2.1 账户类型（P0 现金+储蓄卡，V2.0 全类型/F）**：现金、储蓄卡、信用卡、借出、借入、投资。信用卡支持额度/出账日/还款日/分期，记账自动核减可用额度，出账日自动生成账单汇总。

**信用卡语义（v0.7 重写，解决 C-13）**：信用卡账户维护**两个数字**，且只让一个是权威：

| 概念 | 定义 | 可写性 |
|---|---|---|
| **欠款余额** | Σ 已出账未还 + Σ 未出账消费 − Σ 已还款 | **唯一权威**，与账户余额互为负值 |
| **可用额度** | 总额度 − 欠款余额 | **派生量，只读，不可直接编辑** |
| 已用额度 | 总额度 − 可用额度 | 派生量，只读 |

配套规则：
1. **对账修正的是欠款余额**，可用额度随之自动重算（派生量手改一律被忽略并提示）。
2. **分期不自动展开**：分期是「已入账的一笔消费 + 一组待用户确认的还款计划」；用户确认后生成多期还款账单，撤销时只删未生成期数，已生成期数逐笔进回收站。
3. **记账不做余额校验**：允许刷爆（符合真实语义），但在流水与账户页对超额给出橙色标记而非拦截。
4. **账单汇总只读**：出账日生成的「本期应还」= 上期未还 + 本期新增 − 本期已还；用户不可直接编辑汇总数字，只能通过对账或还款改变。

**F2.2 账户管理（P0/F）**：余额修正产生「对账调整」账单可追溯；排序、备注、余额隐藏。

**账户管理边界（v0.7 补全，解决 B-07 / C-12）**：
- 删除账户时若被以下对象引用，一律**禁止删除**并列出引用来源：账单、周期规则、预算规则、转账对手方、报销单。提示「先迁移或隐藏」。迁移功能：选择目标账户，把该账户全部账单与规则改写指向目标账户。
- **隐藏余额与对账**：开启「隐藏余额」时，账户详情页与对账页的余额一律显示为 `✱✱✱✱`，并提供「临时显示 5 秒」按钮；对账输入框**不受隐藏影响**（用户需要看到自己输入的数字），但对账结果提示中的差额数字在隐藏态下同样打码。

**F2.3 多币种（P2/C）**：账户级 + 记账级币种，双显示原币/本位币，汇率可锁定。
**F2.4 资产总览（P2/C，V2.0）**：账户合计余额视图；**可追溯净值**（Σ资产 − Σ负债、分账户/分月走势、下钻到明细）归 **V3.0**（对应《02》STORY-10.4）。

**F2.5 信用卡账单周期管理（P2/F，v0.7 新增）**

- 每张信用卡可设：账单日（1–28）、还款日（账单日后 N 天或指定日期）、免息期天数（自动推导）。
- **账单日自动生成账单汇总**：当期（上个账单日次日至本账单日）的全部消费汇总为「本期账单」，含应还金额、最低还款、到期还款日。
- **免息期计算**：从消费日到「该笔消费所属账单的到期还款日」的天数，逐笔可见（这是国内信用卡用户真正在意的数字）。
- **还款日提醒**：见 F6.7 提醒中心（提前 3 天与当天各一次）。
- **与记账的关系**：用信用卡消费即产生欠款（F2.1 双数模型），不需要用户额外操作；还款走 F1.8 的「信用卡还款」类型。
- 付费归属：**免费**。理由：国内信用卡用户的刚需，钱迹/咔皮均免费，收费会被直接对标攻击。

**F2.6 账户对账模式（P2/F，v0.7 新增）**

与 F2.2 的「对账调整」区分：**对账调整**是「一个数字修正余额」，**对账模式**是「逐笔勾对银行流水」。

- 进入某账户的对账模式后，展示该账户全部账单并提供勾选框；用户对照银行 App 逐笔勾选「已核对」。
- 未勾选项即为「存疑账单」，可逐笔编辑、删除或标记为「待查」。
- 存在未勾选项时账户显示「待对账 N 笔」角标；全部勾选后账户标记为「已对账至 <日期>」。
- 对账过程中**不修改任何余额**；若勾对后仍有差额，引导用户走 F2.2 的对账调整补差。
- 来源参照：Actual Budget 的 Reconciling 模式、MoneyWiz/Moneydance 的对账单核对。

**F2.7 资产折旧与增值（P3/C，v0.7 新增）**

针对房产、车辆等固定资产（P5 人群）：

- 账户可设「估值模式」：固定值 / 年折旧率（如 -8%）/ 年增值率（如 +3%）/ 手动调整。
- 系统按持有月数自动计算当前估值，并在资产总览中与原始成本并列展示。
- 折旧为**纯估算**，不改动任何账单记录；用户可随时切回固定值。
- 来源参照：MoneyManager Ex 的资产折旧/增值率。

### M3 账本体系

**F3.1 多账本（P2/C）**：账本间分类、账户、预算独立；随附 8 个精模板（日常/装修/旅行/育儿/宠物/婚礼/项目报销/摆摊副业）；封账（只读归档）与年度结转。

**多账本边界（v0.7 补全，解决 C-06）**：
- **账本内独立**：分类、账户、预算、周期规则、标签、报表口径。
- **全局共享（不随账本切换）**：月起始日、主题与外观、隐藏余额、应用锁、字体大小、音效、AI 额度、通知设置、成员（家庭共享的成员列表）。
- **判定原则**：**凡描述「用户怎么看数据」的属全局；凡描述「数据本身是什么」的属账本**。月起始日是统计口径而非数据，故属全局——但报表页在切换账本时须按当前全局口径重算，并在页头显式标注「记账月起始：10 号」以防误读。
- 修改月起始日时**只重切查询期的日区间**（`daily_stats` 日粒度，统计数据一行都不用重算），即时生效、无进度提示；因其为全局口径，全部账本同步切换展示。

**F3.2 家庭共享（P2/C 独立 SKU）**：邀请制 ≤ 6 人（**仅计活跃成员，已退出成员不占名额**）；角色权限（管理员/成员/只读）；成员维度统计；AA 分摊。依赖官方云同步。**成员为软删除**：退出后记录保留、状态置「已退出」，不再出现在成员选择器中，但其历史账单归属仍指向该记录（显示「已退出成员」，不产生悬空引用）。

**F3.3 家庭协作深化（P3/C，v0.7 新增）**

- **交易归属标记**：每笔账单可标「我的 / TA的 / 共同的」，家庭视图可按归属筛选与统计。
- **交易级评论**：成员可对任意账单留言（如「这笔是什么？」），对方在流水页看到评论角标。评论量小、成本低、家庭沟通价值高。
- **独立登录**：每个成员独立账号，不再是「共享同一个登录」；权限与数据归属按账号区分。
- **只读分享**：可生成一个只读链接/邀请码给财务顾问或长辈，仅可查看不可编辑，可随时撤销。
- **AA 分摊细化**：一笔账单可标记参与人（多选成员）与分摊方式（均分/自定义金额/比例），系统自动计算每人应付与净额，并生成「成员间结算建议」（谁该给谁多少钱）。
- 边界：成员退出时其名下账单**保留**（不删除），归属改为「已退出成员」；账本至少有 1 名管理员，最后一名管理员不可退出（须先转让）。

来源参照：Monarch（Mine/Theirs/Ours + 交易级评论 + 只读顾问分享）、随手记（角色权限）。

### M4 统计报表

**F4.1 基础报表（P0/F）**：月收支结余走势、分类占比环形图（一级/二级下钻）、月对比。
**F4.2 日历视图（V2.0/F）**、**F4.3 高级筛选（V2.0/F，差异化免费）**（分类×标签×账户×成员×金额区间×关键词×时间的组合筛选，结果可导出）、**F4.4 资产走势（P2/C）**、**F4.5 自定义报表与年度账单（P2/C）**（H5 分享页为增长钩子；V3.0 增加消费人格年度报告，见 F10.4）。

**筛选结果导出的口径（v0.7 补全，解决 C-09）**：高级筛选（F4.3）的「结果可导出」与 F7.6 的「导出」是**两条不同路径**，须明确区分：

| 路径 | 能力 | 付费 |
|---|---|---|
| F4.3 筛选结果导出 | 仅导出**当前筛选结果**为 CSV（单表、无格式、无统计 Sheet） | **免费**（属于「高级筛选」体验的一部分） |
| F7.6 导出中心 | Excel 多 Sheet（含统计）、PDF 月度对账单、批量导出、自定义字段、导出模板 | **付费** |

判定原则：**「看一眼并拿走」免费，「加工与呈现」付费**。免费 CSV 不含任何格式与统计，付费导出提供可直接交付的成品。商店描述须写明这条分界，避免被指「说好免费又要钱」。

**F4.6 Sankey 桑基现金流图（P3/F，v0.7 新增）**

- 以「收入来源 → 汇总 → 各支出去向」的双层流向图呈现某记账月的资金流动，替代或补充环形图。
- 可切换维度：按一级分类 / 按二级分类 / 按账户。
- 交互：点击任一节点或流带，下钻到对应账单列表；支持时间范围选择（本月 / 近 3 月 / 自定义）。
- 空态与极值处理：无收入或无支出时给出提示而非空图；节点过小（占比 <1%）时合并为「其他」。
- 来源参照：Monarch Plus（独有）、Actual Budget。付费归属：**免费**（它是报表的一种呈现方式，与 F4.1 同属基础能力）。

**F4.7 多维度交叉分析（P3/F，v0.7 新增）**

- 在报表页支持「维度 × 维度」的交叉透视：分类 × 账户、标签 × 月份、成员 × 分类、商户 × 金额区间。
- 输出形式：矩阵表（行=维度 A，列=维度 B，单元格=金额）+ 可切换热力着色。
- 可保存为「我的报表」（保存筛选与维度组合，一键复现）。
- 来源参照：Firefly III 的 tags 报告、MoneyWiz 的分组报表。

**F4.8 资金年龄（Age of Money）（P3/F，v0.7 新增）**

- 定义：**当前花掉的每一块钱，其来源收入距今天数的加权平均**。算法（FIFO）：把每笔收入按时间排队，每笔支出消耗最早未消耗的收入，支出日与所耗收入日的差值即该笔支出的「资金年龄」，按金额加权平均。
- 展示：一个数字 + 近 6 个月趋势线 + 一句话解读（「你的钱平均能撑 43 天才花掉，比上月更从容」）。
- 边界：数据不足 2 个月或收入笔数 < 5 时显示「数据积累中」；存在负值时（先花后收）取 0 而非负数。
- 来源参照：Actual Budget（独有指标）。付费归属：**免费**。

### M5 预算管理

**F5.1 总预算（V2.0/F）**：月支出总额，首页进度条 + 按剩余天数推算日均可用。
**F5.2 分类预算（V2.0 限免 → P2/C）**：一/二级限额，80% 预警、100% 提醒。
**F5.3 预算周期（P2/C）**：自定义起始日（1–28 号，发薪日记法）、自定义周期（旅行专项）、结余滚存。

**预算边界（v0.7 补全，解决 C-05 / B-15）**：
- 预算统计**一律排除**对账调整、转账、借贷（口径见 G-2）。
- 预警触发时机：每笔入账后立即重算；跨 80%/100% 阈值时按 G-3 发**响铃**通知。
- 周期免确认入账触发跨阈值时，按 G-3 的例外规则同样响铃（夜间降级为次日汇总）。
- 预算周期与「记账月」的关系：预算周期默认跟随「记账月起始日」（G-1）；用户可单独设预算起始日覆盖之，此时报表月与预算月不同，UI 须在预算页标注「预算周期：10 日–次月 9 日」以防误读。
- 结余滚存：正结余滚入下期，负结余（超支）**默认不滚入**（避免「上月超支导致本月无预算」的挫败感），但用户可开启「超支也滚存」。

**F5.4 「安全可花」单值（P2/F，v0.7 新增）**

首页展示一个核心数字：**今天可以放心花多少**。

- 计算：`安全可花 = 可用资金 − 未来账单预留 − 未达成目标的待拨付 − 本月剩余刚性支出预留`，再按剩余天数平摊得到「日均安全可花」。
  - 可用资金 = 现金 + 储蓄卡余额（不含信用卡额度、不含投资）
  - 未来账单预留 = **本记账月**内周期规则待生成账单之和（口径见 G-1）
  - 目标待拨付 = 各储蓄/沉淀目标**本记账月**尚未划拨的金额
  - 刚性支出预留 = 用户标记为「刚性」的分类（如房贷、房租）的剩余预算；**「刚性」是分类上的一个布尔标记**（分类编辑页可设，仅一级分类可标，见 F1.2）
- 展示：一个大数字 + 三行拆解（可展开看明细）+ 一句话结论（「今天可以放心花 ¥86」）。
- 边界：结果为负时显示「本月已超支，建议暂停非必要支出」并给出最大超支分类；无预算设置时隐藏该卡片（引导用户先设预算）。
- 隐私：隐藏余额模式下该数字**一并打码**（口径见 G-7）。
- 来源参照：PocketGuard 的 Leftover / In My Pocket（其核心功能）、YNAB 的 Ready to Assign。

**F5.5 沉淀基金 / 储蓄目标（P2/F，v0.7 新增）**

把一年一次的大额支出（保险、车检、年费、旅行、礼物）摊成月度小额，消灭「预算黑洞」。

- 定义一个目标：名称 + 目标金额 + 截止日期 + 关联账户（可选）。
- 系统自动计算「每月需存入」=（目标金额 − 已存）/ 剩余月数，并在预算页显示「本月待存」。
- 存款动作：手动「存入一笔」（生成一笔从可用账户到目标虚拟账户的内部转账，不计入收支）；或开启「自动按月划拨」（周期规则的一种，走 F6.1 引擎）。
- 进度可视化：环形进度 + 剩余天数 + 逾期提示（截止日已过而未达成时标记「未达成」但保留）。
- 与 F5.3 结余滚存的关系：沉淀基金是「专项预留」，预算结余是「通用结余」，二者独立计算，互不占用。
- 来源参照：YNAB 的 Sinking Fund（四法则之二「Embrace Your True Expenses」）、Firefly III 的 Piggy Banks、Monarch 的 Goals 3.0。

**F5.6 目标体系（P2/F，v0.7 新增）**

把「存钱目标」与「还债目标」分离（Monarch Goals 3.0 的设计）：

| 目标类型 | 适用 | 特有逻辑 |
|---|---|---|
| 储蓄目标 | 攒钱买物、应急金 | 进度 = 已存 / 目标；可设截止日 |
| 还债目标 | 房贷、车贷、信用卡分期 | 进度 = 已还 / 总欠款；含剩余期数、剩余利息、预计还清日 |
| 限额目标 | 控制类（本月餐饮 ≤ 2000） | 复用 F5.2 分类预算，不重复建设 |

- 还债目标与 F5.8 贷款摊销联动：用户追加还款时，目标页显示「提前 X 个月还清、少付利息 ¥Y」。
- 来源参照：Monarch Goals 3.0、YNAB Targets。

**F5.7 预算方法论切换（P3/F，v0.7 新增）**

预算引擎抽象为「方法论层 + 执行层」，用户可切换四种预设方法论：

| 方法论 | 核心机制 | 适配人群 |
|---|---|---|
| 自定义（默认） | 当前的总预算 + 分类预算 | 全量 |
| 信封法 | 每类一个信封，独立滚存，超支不许跨类挪用 | P2 家庭 |
| 零基预算 | 收入逐项分配至「归零」，未分配金额必须为 0 | P2 / P5 |
| 50/30/20 | 按需/想要/储蓄三档比例 | P4 新手 |

- 切换方法论**不修改历史数据**，只改变预算页的呈现与校验规则；切换时给出对照预览。
- **限额目标（F5.6）跨方法论保留**：限额目标底层即「分类预算」，四套方法论下**全部继续生效**，仅呈现方式随方法论变化（自定义=分类预算行、信封法=信封、零基=已分配项、50/30/20=落入对应档位的分类），不产生第二套数据、不因切换失效。
- 来源参照：WalletHub（5 种方法论）、HomeBank（信封法完整实现）、YNAB（零基）、budgetzero。

**F5.8 贷款摊销与提前还款测算（P3/C，v0.7 新增）**

面向房贷/车贷用户（P5）：

- 创建贷款账户时录入：本金、年利率、期数、还款方式（等额本息/等额本金）、首次还款日。
- 系统生成**完整摊销计划表**：每期本金/利息/剩余本金，可视化图表。
- **提前还款测算**：输入「额外还款 X 元/月」或「一次性还 Y 元」，输出「可提前 N 个月还清、少付利息 ¥Z」，两种还款方式分别给出对比。
- 每期还款自动生成**两笔**账单（走周期引擎，见 F6.1），用户确认后入账：**利息部分**计入支出统计与预算（真实资金成本）；**本金部分**不计入收支统计与预算（是负债减少，非消费，口径见 G-2），仅减少负债账户余额。
- 来源参照：YNAB Loan Payoff Planner、Monarch Goals 3.0 还债目标、MoneyWiz 债务模块。

### M6 效率记账

**F6.1 周期记账（V2.0 限免 → P2/C）——规则引擎规格**：频率（日/周/月/年/自定义间隔 N）；月内锚定日遇短月自动顺延至月末（如 31 号 → 2 月 28/29 号）；免确认直接入账 vs 通知内确认（通知展开预览一键确认/跳过）；结束条件（永久/截至日/N 次）；编辑规则不追溯已生成账单；生成账单带来源标记可整体撤销当次批量。

**统一周期规则引擎（全产品只有这一套调度机制）**：以下三类「自动生成账单」全部走本引擎，各自带类型标识，**不另建机制**——周期记账（`recurring`，锚定日触发）/ 储蓄与沉淀目标自动划拨（`savings_transfer`，记账月首日触发，见 F5.5）/ 贷款每期还款（`loan_repayment`，每期还款日触发，见 F5.8）。

**周期记账边界（v0.7 补全，解决 C-05 / C-10 / B-14）**：
- **免确认入账的通知口径**：走 G-3 静默通知；若击穿预算阈值则升级为响铃（夜间降级）。
- **系统时间被改**：周期规则按「上次执行时间 + 间隔」推进，不依赖「今天」；用户改系统时间到未来，不补生成账单，下一个自然触发点按真实时间推进（防止时间跳跃批量生成）。
- **回收站恢复与周期规则**：若删除的是周期生成的账单，恢复后该账单**保留来源标记但不恢复与规则的关联**（仅规则的下次生成仍按原计划）；已被整体撤销的批次，其单笔不可单独恢复（提示「该批次已撤销，请恢复整个批次」）。
- **规则的暂停与恢复**：规则可暂停（不生成）不删除；恢复后从下一个触发点继续，不补历史。
- **修改规则的边界**：修改金额/分类/频率后，**已生成账单不变**，仅影响后续；修改生效时间点可在确认框中选「从下次触发起」或「立即（下次触发即为新版）」，二者等价但文案不同。

**F6.2 模板记账（P2/C）**、**F6.3 账单导入（P2/C）——向导流程规格**：选来源（支付宝/微信/云闪付/竞品）→ 文件选择或系统分享进入 → 解析预览（展示自动分类匹配率，不可识别项红色标记待人工确认）→ 去重（**指纹 = 日期+金额+币种+商家名**，命中则跳过并计数）→ 导入报告（成功 N / 去重 M / 待确认 K）。

**F6.3 导入扩展（v0.7 补全）**：
- 除国内来源外，V3.0 增加 **OFX / QFX / QIF / MT940 / CAMT.053** 支持（海外与部分银行导出格式，参照 MoneyWiz 与 Firefly III）。
- 去重指纹**可配置**：默认「日期 + 金额 + **币种** + 商家名」，用户可再追加「账户」维度（同一笔在多账户出现时避免误判）。**默认跨来源交叉去重**（先从支付宝导入、后从银行导入同一笔判为重复），用户可关闭该开关改为仅同来源内去重；币种参与指纹以区分 100 USD 与 100 CNY。
- 导入前可套用**规则引擎**（F6.8）批量自动分类，导入报告展示「规则命中 N 笔」。

**F6.4 票据 OCR（P2/C）**、**F6.5 语音记账（并入 F10.1）**、**F6.6 自动记账（P3 预研，不进主线）**。

**F6.7 提醒中心（P2/F，v0.7 新增）**

把「周期记账」的被动生成升级为「主动管家」的推送体系。统一入口：首页顶部状态条 + 「我的」页「提醒」区块。

| 提醒类型 | 触发规则 | 级别 |
|---|---|---|
| 信用卡还款日 | 到期前 3 天、当天各一次 | 响铃 |
| 订阅到期前取消 | 识别到连续扣款的订阅，在其「下次扣款前 3 天」提醒（可一键标记「不再需要」并给取消路径指引） | 响铃 |
| 预算分级 | 80% / 100% 各一次（每周期每分类最多各一次，避免重复轰炸） | 响铃 |
| 余额不足预警 | 「安全可花」为负或某账户余额低于用户设的阈值 | 响铃 |
| 异常支出 | 单笔金额 > 该分类近 90 天 P90 的 2 倍，或当日合计 > 近 30 日均值 3 倍 | 静默（可升级为响铃） |
| 周期账单已入账 | 免确认入账后 | 静默 |
| 对账提醒 | 每月记账月首日提醒上月未对账 | 静默 |
| 储蓄目标待存 | 每月记账月首日 | 静默 |
| 备份提醒 | 距今上次备份 > 30 天 | 静默 |

- 所有提醒**可逐项开关**，且提供「全部静音」总开关（默认关）。
- 提醒历史可查（近 90 天）。
- 来源参照：咔皮（三合一提醒）、PocketGuard、Simplifi（unusual spending watchlist）、MoneyWiz。

**F6.8 规则引擎（P2/F，v0.7 新增）**

自动化能力的核心，直接对标 Actual Budget 的完整设计。

**规则结构**：

| 组成 | 说明 |
|---|---|
| 条件（IF） | 字段（金额/备注/商户/账户/分类/来源）× 运算符（等于/包含/大于/小于/介于/正则）× 值；多条件支持 AND / OR |
| 动作（THEN） | 设置分类 / 设置标签 / 设置账户 / 设置成员 / 标「不计入收支」/ 标记待报销 / 加备注前缀 |
| 执行阶段 | **pre**（导入/录入前预处理，如先归户）与 **post**（导入后清理，如批量改分类）；同阶段内按优先级顺序执行 |
| 优先级 | 整数排序，可拖动调整 |
| 适用范围 | 手动记账时 / 周期生成时 / 导入时 / 分割子笔 |

**必要能力**：
- **变更预览**：保存规则前，展示「将命中 N 笔历史账单」，可展开查看明细，确认后才生效（默认**不回溯**已存在账单，用户可显式选择回溯）。
- **试运行**：对一条规则可「在最近 100 笔上试运行」，展示每条的结果。
- **模板化动作**：动作值支持简单模板（如备注前缀 `[报销]`）；不做完整脚本语言（避免复杂化与安全风险）。
- **规则列表**：可排序、启停、复制、删除。
- 来源参照：Actual Budget（pre/post 双阶段 + 优先级 + 模板化动作 + 预览）、Firefly III（Payee 规则）、Monarch（Refine Rules）。

**F6.9 短信自动记账（P3/预研，v0.7 新增）**

国内无 Plaid 类聚合器的可行自动记账路径：Android 端读取银行/支付类短信（如「您尾号 1234 的储蓄卡支出 25.00 元」），解析金额、时间、商户并生成待确认账单。

**合规与边界（必须先过评估才立项）**：
- 需 `READ_SMS` 权限，属**敏感权限**，与 M8.3「不申请无关权限」的宪法条款存在潜在冲突，须单独评审并明确「这是用户主动开启的可选能力」。
- **仅在用户显式开启后启用**，默认关闭；开启页须完整说明数据仅本地解析、不外传。
- 解析结果**一律进入「待确认」列表**，不直接入库（避免误判污染账本）。
- 上架风险：应用商店对短信权限审核严格，须准备功能必要性说明；iOS 不可用（系统限制），故 Android 独占。
- 来源参照：XPENC（Flutter 短信捕获）。

### M7 数据管理

**F7.1 本地存储（P0/F）**：本地优先，未登录可完整使用。
**F7.2 官方云同步（P2/C，核心付费点）——冲突策略规格**：账单级采用基于共同祖先的三方合并（3-way merge），无共同祖先或字段冲突时取最后写入并生成冲突副本（两个版本都保留，用户在「冲突中心」裁决）；同步范围含账单/分类/账户/账本/预算/设置；同步延迟目标 ≤ 10 秒（同账号活跃端）。
**F7.3 云同步（WebDAV：V1.0 已有整库替换、V2.0 升级 change_log 增量；iCloud：V3.0/F，差异化）**、**F7.4 备份（P0 手动 / P2 自动云备份付费）**、**F7.5 竞品数据导入（V2.0/F，获客武器）**（钱迹/随手记/挖财/鲨鱼/有鱼/网易有钱 + 通用 CSV 映射向导）、**F7.6 导出（V3.0/C）**（Excel 含统计 Sheet、CSV、PDF 月度对账单）、**F7.7 回收站（V2.0/F，V1.0 已全链路实现）**（30 天）、**F7.8 操作日志（V3.0/F）**（90 天）。

**F7.2 同步范围的完整清单（v0.7 补全，解决 C-06 / INV-3）**：

| 类别 | 项目 | 是否同步 |
|---|---|---|
| 数据资产 | 账单、分类、账户、账本、预算、周期规则、标签、成员、报销单、储蓄目标、投资持仓、贷款计划 | **同步** |
| 数据资产 | 账单附件 | 不同步（V2.0），V3.0 评估 |
| 可同步设置 | 月起始日、隐藏余额、字体大小、音效、保存后停留、提醒开关 | **同步** |
| 本地偏好 | 主题、外观模式、首页卡片布局、记账页布局偏好 | **不同步**（设备偏好，跨端同步会互相覆盖） |

判定原则：**描述「数据是什么」的同步；描述「这台设备怎么看数据」的不同步**。

**F7.4 备份边界（v0.7 补全，解决 B-09 / B-10 / B-11）**：
- **密码错误**：校验失败提示「密码错误」，允许重试 3 次，3 次后建议「放弃并使用其他备份文件」；不锁定、不删除文件。
- **文件损坏**：解析失败时提示「备份文件已损坏或不完整」并给出「文件大小 / 生成时间」等元信息（若可从头部读出）；不覆盖现有数据。
- **目标版本更高**：拦截并提示「需要升级 App 至 X.X」，同时给出兼容说明。
- **已有更新数据**：恢复为**覆盖式**，但执行前必须展示「当前数据的最后账单日期 / 账单数」与「备份文件的数据范围」对比，用户确认后才覆盖；覆盖前自动生成「恢复前备份」。
- **存储空间不足**：生成备份前预检可用空间，不足时提示所需空间并可选择「不加密直接导出（省去临时文件）」或取消。
- **备份内容**：V2.0 起为「数据库快照 + 附件目录」打包；文件名含版本号与时间戳。

**F7.7 回收站边界（v0.7 补全，解决 C-10 / C-11）**：
- 回收站 30 天；到期后每日巡检任务物理清除。
- **删除账单时的附件**：标记为孤儿附件，随账单恢复而恢复（细则见 F1.5）。
- **周期账单的恢复**：见 F6.1 边界。
- **合并产生的软删除分类**：可在回收站看到并撤销合并（V2.0 起）。
- **批量删除**：操作日志中记录「一次批量删除」，可整体撤销（30 天内）。

**F7.9 开放 API 与 MCP 接口（P3/C，v0.7 新增）**

- **本地 HTTP API**（局域网可访问，默认关闭，需用户显式开启并设 token）：读写账单、分类、账户、预算；支持 Webhook 推送（新账单、预算跨阈值）。
- **MCP 接口**：让 LLM（如 WorkBuddy / Claude）通过 MCP 协议直接查询与操作账本（「帮我看看这个月餐饮花了多少」「把这 5 笔标为报销」）。参照 BeeCount。
- **安全边界（硬约束）**：默认关闭；开启须设访问令牌；**仅局域网，不暴露公网**；所有外部写入**必须留操作日志**（可追溯、可撤销）；只读模式与读写模式分开授权。
- 来源参照：Actual Budget（API）、Firefly III（REST + OAuth2 + Webhook）、BeeCount（MCP）。

### M8 安全与隐私

**F8.1 应用锁（P0/F）**、**F8.2 数据加密（P0/F）**（SQLCipher 类本地加密 + TLS + 余额隐藏）、**F8.3 隐私承诺（P0 宪法级）**：无广告、无开屏、不申请无关权限、不做用户画像、永不做金融导流。写入商店描述与官网，并寻求第三方认证（绿色应用公约类）背书。

**F9.2 主题系统（P0 / F，v0.4 新增）——内置 10 套主题**

10 套主题**全部免费、无需解锁**，每套提供浅色与深色两态（合计 20 套配色组合）；外观模式三态：跟随系统（默认）/ 浅色 / 深色。切换即时生效、全局覆盖（含弹窗、Toast、日历抽屉、桌面小组件），无需重启；杀进程后保持。

**归属决策**：主题持久化于本地设置，**不参与云同步**。理由是主题属于设备偏好而非数据资产——手机用深色、平板用浅色是合理组合，跨端同步会互相覆盖（云同步范围含「设置」需按此排除主题与外观两项，见 F7.2）。

**设计约束**（五条，均为可验收项）：

1. **分类色板与收支语义色跨主题固定**。数据语义不应随皮肤漂移：同一分类在 10 套主题下取色一致，收入红 / 支出墨保持稳定。否则用户换主题后报表读不出既有含义。
2. **对比度全部达 WCAG AA**：正文 ≥ 4.5:1，大字与图形 ≥ 3:1。浅彩主题的实心按钮（如 FAB、保存键）自动改用深色前景——白字在浅橙/浅杏底上仅 1.8–2.8:1，不可读。此项由 CI 自动校验，覆盖 20 套组合。
3. **色相在色环上分散并统一保留「一冷一暖」的基因**（主色 + 强调色），保证 10 套彼此可辨识、且都不是半成品。
4. **淡彩层（chip 底、图标底、hover 底）由品牌色 + alpha 即时合成，不落不透明色值**。结构色（页面底、卡片、文字、分隔线）必须不透明——半透明结构色的实际渲染色取决于它叠在什么之上，会让同一令牌在不同位置呈不同颜色、并让对比度无法静态校验。深色态的 alpha 须高于浅色态（26% vs 16%），否则淡彩在深底上不可见。装饰层（光斑、阴影、遮罩、Toast 底）本就用真 alpha。
5. **语义色（收入 / 支出 / 成功 / 警示）的淡彩层保持不透明**，理由同约束 1——跨主题恒等优先于通透感。

### M10 AI 能力（v0.3 新增模块）

设计原则：AI 做确定性的增强而非炫技；所有 AI 功能必须有无 AI 的降级路径；免费额度制控制成本。

**F10.1 AI 识别记账（V2.0，免费 10 次/月，AI Pro 不限）**。三个入口：截图（相册选图或系统分享进入，识别金额/商家/日期并预填）；语音（「早餐 18」口语解析）；文本（粘贴账单文本）。识别结果进入标准记账页预填（不是黑箱直接入库——咔皮的误判教训），用户一键确认或修正。模型策略：端侧小模型（金额/日期抽取）优先，复杂场景走云 API；图片仅用于识别、传输存储加密、不用于训练。

**AI 额度边界（v0.7 补全，解决 C-14）**：
- **重置口径**：按**记账月**（G-1）重置，与产品其他周期口径一致，避免「月」的两种解释。
- **计数范围**：仅**成功的识别结果返回**计入额度；因网络失败、图片无法识别、用户主动取消的**不计入**。
- **多端计数**：V3.0 前无账号体系时，额度为**设备级**（换设备独立计数）；V2.0 账号上线后改为**账号级**并在同步时对齐（取各设备用量之和，防刷）。
- **用尽后**：给出「本月额度已用完，下月 X 日恢复」并展示 AI Pro 入口（付费墙触点，见 §10.3）；不打断当前操作。

**F10.2 AI 消费周报/月报（P2，简版免费/完整版 AI Pro）**。主动推送式（咔皮优点 2）：每周日晚推送「本周消费画像」——分类占比、环比变化、异常大额、可优化项。免费简版 1 屏；Pro 完整版含趋势分析与建议。文案基调：只陈述 + 只夸不贬（咔皮翻车教训），可完全关闭。

**F10.3 订阅浪费检测（P3/AI Pro）**：识别周期性扣款模式，标记连续 90 天无交互场景的订阅（如音乐/网盘会员），提示「取消可年省 ¥N」。基于本地数据规则 + AI 辅助判断，不联网查证。

**F10.4 消费人格年度报告（P3/免费）**：年度账单的社交货币升级版——「你是精打细算的松鼠型选手」+ 可分享海报。增长钩子，免费开放。

**F10.5 现金流预测（P3/AI Pro）**：基于周期规则与历史均值预测未来 30 天账户余额曲线，提前暴露赤字日（Simplifi 优点）。

## 八、非功能需求

冷启动 ≤ 1.5s（中端 Android，加严，对齐钱迹秒开心智）；记账本地落库 ≤ 200ms；万条账单流水 60fps、报表 ≤ 1s；安装包 ≤ 40MB；**主题切换 ≤ 100ms 且不闪屏（首帧即目标主题）**。兼容：iOS 15+、iPadOS 15+、Android 8.0+（API 26）、Android Pad 含 2GB 内存档（降级：关动画、报表惰性渲染）。离线全功能；同步断点续传；数据库迁移向前兼容。

**v0.7 增补非功能项**：
- **规则引擎性能**：1000 笔账单批量套用规则 ≤ 3s，且不阻塞 UI（须在后台 isolate 执行）。
- **投资行情刷新**（V3.0）：手动刷新单次 ≤ 5s，自动刷新每日一次（低功耗时段）；行情不可用时展示上次价格并标注时间。
- **Sankey 图渲染**（V3.0）：500 节点内渲染 ≤ 800ms。
- **本地 API/MCP 响应**（V3.0）：单次查询 P95 ≤ 500ms。

合规：个保法最小必要、账号注销与数据彻底删除、出海另评 GDPR。**v0.7 新增合规项**：短信读取（F6.9）须单独评审权限必要性与商店审核材料；本地 API 默认关闭且不暴露公网；投资持仓的行情数据来源须取得授权或使用免费公开源并标注。

质量：核心逻辑测试覆盖 ≥ 70%、崩溃率 ≤ 0.1%、同步冲突自动解决率 ≥ 95%、AI 识别准确率 ≥ 95%（金额与日期字段，内测集口径）、**20 套主题配色对比度自动校验零失败（WCAG AA，正文 4.5:1 / 大字与图形 3:1）**。

## 十、商业化策略（v0.3 拓宽版，v0.7 顺延至 V4.0）

> **v0.7 说明**：本节结构与定价保持不变，**生效版本由 V2.0 顺延至 V4.0**。V2.0/V3.0 的功能全部免费，商业化只在 V4.0 开启。这一调整的理由：付费说服力来自「产品已经很厚」，在功能未铺满时上付费墙，付费率低且差评风险高；推迟到 V4.0 可让 V4.0 上线即拥有完整的付费理由（云同步 + AI Pro + 多账本 + 家庭 + 深度资产）。

### 10.1 付费墙结构

免费层（永久）：记账核心全量（含 AI 每月 10 次）、现金/储蓄卡/信用卡/借贷账户、基础报表、总预算、高级筛选、回收站、WebDAV 同步、本地备份、竞品数据导入、消费人格年度报告；**v0.7 新增免费项**：交易类型化、规则引擎、提醒中心、安全可花、沉淀基金、目标体系、报销工作流、Sankey、交叉分析、资金年龄、预算方法论、信用卡账单周期、对账模式。

### 10.2 五层变现组合（核心拓宽）

**L1 核心订阅与买断（基本盘）**：个人 Pro 订阅 ¥12/月、¥68/年；终身卡 ¥168（首发限量）。参照系已修正：钱迹 ¥36/年·¥128 买断意味着我们贵约一倍，对价必须讲得通——云同步四端 + 高级筛选/回收站等免费诚意在前 + AI 能力，商店描述需主动对比。Omi 数据（买断占收入 85%）修正 v0.2 判断：**买断与订阅双轨并重**，终身卡不做限量饥饿、常态化供应。
**L2 家庭计划**：¥128/年（6 成员，含全部 L1 权益 ×6），锚定双人记账场景。
**L3 点购层（破冰与个性化）**：Starter Pack 首购包 ¥6（终身卡 9 折券 + 3 个月 Pro + 限定图标包——Omi 验证的低门槛首购设计，把「从未付费」变成「付过 6 块」）；主题皮肤/图标包 ¥6–12/套；记账伙伴角色包 ¥6–12。点购毛利率 100%，且是 P4 人群的主转化路径。
**L4 AI Pro（能力订阅）**：+¥30/年（叠加在年订阅上）或独立 ¥98/年。覆盖：AI 识别不限次、完整版周报/月报、订阅浪费检测、现金流预测。定价逻辑 = AI 单位成本 × 预估用量 × 3 倍毛利垫；端侧模型优先控制边际成本。
**L5 生态延伸（V4.1+ 评估，不承诺）**：报销助手（打通「记报销账单 → 生成报销单 → 追踪回款」，面向有报销刚需的职场人与小团队，天然的 toB 切入点）；联合会员（与坚果云等 WebDAV/网盘服务互推，用户群高度重叠）；**v0.7 新增**：开放接口的专业版（F7.9 的高级能力，如 Webhook 与更细粒度权限）；坚决不做：金融导流、数据变现、广告。

### 10.3 转化漏斗（量化口径）

自然使用 → 付费触点曝光（AI 额度用尽提示、限免到期倒计时、导入超过 500 条提示）→ 首购破冰（Starter Pack ¥6，目标付费用户 40% 经由首购包进入）→ 订阅升级（7 天试用）→ AI Pro 叠购 → 续费（到期前 30 天推送「你的年度数据报告」留存钩子）。北极星：月活跃记账天数 ≥ 15 用户占比；健康度：付费转化 ≥ 3%、年付占订阅 ≥ 60%、首购包→订阅升级率 ≥ 25%、AI Pro 叠购率 ≥ 15%。

**v0.7 补充**：V2.0/V3.0 期间**不设任何付费触点**（含 AI 额度用尽提示），AI 免费额度用尽只做提示不做推销；付费触点统一在 V4.0 开启。这是「先做厚产品再谈钱」策略的执行保障。

### 10.4 收入结构假设（参照 Omi 实测口径修正）

买断 45%、订阅 35%（其中 AI Pro 占订阅收入 20%）、点购 10%、家庭 10%。此为 24 个月目标结构，用于财务模型基线；每季度按实测校准。

### 10.5 留存钩子：记账契约（借鉴咔皮、改造其机制）

连续记账 7 天 → 赠 1 个月 Pro；连续 30 天 → 赠 3 个月；连续 100 天 → 赠终身卡抽奖资格（每月抽 10 名）。与咔皮「每日 +1 天」的差异：里程碑式成本可控、且避免把会员变成「不记账就亏」的焦虑源（情绪价值设计原则同样适用于此）。本质：用虚拟权益买「记账习惯」，习惯即留存，留存即付费前提。**因商业化后移至 V4.0，奖励以「V4.0 权益券（V4.0 起生效）」形式发放，并在获得时同时发放非付费类奖励（徽章/装扮）以确保当下可感知**。落地方案见 F9.6。

## 十二、开放问题（评审决策项）

1. 出海是否列入 V3.x 议程（影响双语与双轨定价提前量）。

6. 后端同步服务自建 vs BaaS。
7. **投资行情数据源选型**（v0.7 新增）：免费公开源（不稳定、合规存疑）vs 商业 API（有成本）vs 纯手动录入（零成本、体验差）。

## 十三、术语表

**本地优先（Local-first）**：数据主副本在设备本地，云同步为增量复制，离线不降级。
**三方合并（3-way merge）**：以共同祖先版本为基准的冲突合并策略。
**首购破冰（Starter Pack）**：低单价一次性购买，用于跨越「从未付费」心理门槛。
**锚定日**：周期记账在月内的触发基准日，短月自动顺延。
**消费人格**：基于消费数据的风格化画像，用于年度报告社交传播。
**设计令牌（Design Token）**：以命名变量集中定义的颜色、间距、圆角等视觉常数；主题切换即替换令牌取值，页面代码中不含硬编码色值。
**主题（Theme）**：一套命名的设计令牌取值组合；本产品的主题 = 中性基调 × 品牌色相 × 明暗，共 10 套 × 2 态。
**记账月（Accounting Month）（v0.7 新增）**：由用户设置的「月起始日」定义的统计周期，是全产品唯一的「某笔账单属于哪个月」判定口径（见 G-1）。默认起始日 1 号时等于自然月。
**分割交易（Split Transaction）（v0.7 新增）**：把一笔支付拆分为多个分类的子笔，父笔与子笔金额必须对平；父笔计一次账户变动，子笔各自进分类统计。
**规则引擎（Rule Engine）（v0.7 新增）**：以「条件 + 动作 + 执行阶段 + 优先级」描述自动化行为，在录入/导入/周期生成时自动施用于账单。
**安全可花（Safe-to-Spend）（v0.7 新增）**：从可用资金中扣除未来账单、目标待拨付与刚性支出预留后的日均可自由支配金额。
**沉淀基金（Sinking Fund）（v0.7 新增）**：为可预见的大额支出（年费、保险、车检）预先按月摊存的目标账户。
**资金年龄（Age of Money）（v0.7 新增）**：按 FIFO 计算的「花掉的一块钱平均在手里停留多少天」，衡量财务从容度。
**对账模式（Reconciliation）（v0.7 新增）**：逐笔勾对银行流水并标记「已核对」的过程，与「对账调整」（用一个数字修正余额）区分。

| 令牌结构 | 单层（语义变量直挂色值） | 双层：中性层（tone）× 品牌层（theme）× 明暗 |
| 对比度保障 | 按单套人工核对 | 20 套全量自动校验，CI 必过 |
| 持久化 | — | 2 个本地偏好 key，不入云同步 |
| 页面 | — | 新增主题页 SP-5-02；我的页加主题入口与外观选择（SP-5-03） |

### 14.3 功能规格

#### 14.3.1 页面与交互

**入口。** 「我的」页（SP-5-03）新增一行「主题」，右侧显示当前主题名与三枚色点（机身底 / 主色 / 强调色），点击进入主题页 SP-5-02；同页内嵌「外观」三态选择器。

**主题页 SP-5-02 元素。**

- 外观三态分段控件：跟随系统（默认）/ 浅色 / 深色；
- 主题网格：每张色卡含三枚色点（机身底、主色、强调色）、主题名、气质标签（如「默认主题 · 炭黑 × 橘红」「清爽 · 青绿 × 蜜桃」）；当前选中项显示勾选态；
- 页面无「保存」按钮——点选即生效；无「恢复默认」——**素白**即默认值。

**切换链路。** 点选主题 → 写入本地偏好 → 通知主题 Provider → 替换 `ThemeData` → 全局重建配色 → 弹 Toast「已切换主题：<名称>」→ 同步更新「我的」页入口行的名称与色点。外观切换只改明暗解析，不动主题选择；两者正交，互不覆盖。

**原型直链（仅用于评审/截图，不属产品功能）**：`14-设计规范·高保真UI.html`（默认素白）；主题切换演示亦见 `03-交互原型.html`。

#### 14.3.2 边界与异常

- 主题注册表为**编译期只读常量**，不接受运行时增删；**ID 一经发布不可改名、不可改序**（用户偏好按 ID 持久化，改名等于丢偏好）。
- 读到**未知主题 ID** 时回落**素白 `subai`**，不抛错、不白屏（前向兼容：后续版本若下线某主题，老用户偏好不崩）。
- 外观为「跟随系统」时，系统亮暗切换须在 1 秒内跟随；外观被显式设为浅色/深色后，系统切换不影响 App。
- 杀进程重启后主题与外观保持一致。
- 首帧即为目标主题，**不得出现「先浅色默认、后跳目标主题」的闪屏**（见《04》§16.2.2）。
- 切换耗时 ≤ 100ms；`ThemeData` 不得在 `build` 内重算（见《04》§16.3.4）。

| 风险 | 影响 | 处置 |
|---|---|---|
| 20 套配色维护成本高，改一处漏三处 | 视觉不一致、对比度失守 | 令牌集中定义 + CI 全量门禁（《04》§16.5.2） |
| 免费 10 套削弱「限定主题皮肤」付费点 | 商业化 | 《01》F9.4 已定口径：点购卖限定款与陪伴感，不把基础主题锁起来卖 |
| ~~浅彩主题 hero 卡被压暗后通透感下降~~ | 观感 | **已缓解**：配色换代时 hero 两端在设计期即迭代至白字 ≥ 4.75:1，运行时不再触发压暗（《04》§16.1.6 ④） |
| 淡彩层改 alpha 后对比度校验失真（按声明值而非渲染值） | 门禁失效 | 派生走 `inkForLayers()` 对全部叠合底取最不利者；语义淡彩层保持不透明（《04》§16.1.1 透明度政策） |
| 存量硬编码颜色清理遗漏 | 主题切换后局部不跟随 | INV-5 自动扫描 + 清单化推进（T7） |
| 小组件取色与主题切换不同步 | AC8 不达标 | 契约先行、变更即刷（《04》§16.3.5） |
| 启动闪屏底色与主题不符 | 闪白/闪黑 | 启动图用中性色，首帧同步读偏好（《04》§16.2.2） |
| `ColorScheme.fromSeed` 被误用 | 对比度不可控 | 《04》§16.1.7 明令禁止，评审检查项 |
