## 1. 规范体系：三层效力

| 层 | 手段 | 效力 | 覆盖 |
|---|---|---|---|
| L1 机器强制 | `flutter_lints` + analyzer errors + CI | 违反即构建失败 | 风格、类型、异步、若干红线 |
| L2 评审强制 | PR 清单 | 可追溯 | 分层、事务、隐私、布局硬编码 |
| L3 约定 | 文档 / AGENTS.md | 靠习惯 | 命名、提交、文档同步 |

**原则**：同一规则只出现在一层。能进 CI 的不靠评审。

### B 组：正确性红线

| # | 规则 | 执行 |
|---|---|---|
| B1 | 金额 **int64 分**，禁 `double` 运算与显示（用 `Money` / `formatAmount`） | 评审 |
| B2 | 业务取时必须走注入 `Clock`；`DateTime.now()` 仅限 `core/time` 与少数 UI 显示 | 评审 |
| B3 | 仓储写路径用 `runWrite`（事务 + change_log + `Result`）；异常捕获用 `on Object` 防 `Error` 漏网 | 评审 |
| B4 | 禁止 `print`；`unawaited_futures` / `discarded_futures` / `use_build_context_synchronously` 为 **error** | lint |
| B5 | 可失败操作返回 `Result<T>` / `Failure`，不把异常当控制流穿透到 UI | 评审 |
| B6 | `build()` 内禁止 IO / 查库 / 网络 / 创建 Controller | 评审 |

> **B3 实况**：`database.dart` 的 `transaction()` 已用 `catch (_)`（捕获 `Object`，含 `Error`）→ 不会事务悬挂。**唯一正确做法**，新增事务代码不得退回 `on Exception`。
> ⚠️ `DateTime.now()` 全 `lib/` 共 37 处，`core/time` 之外仍有分布（`app_date_picker` / `category_manage_page` / `trash_page` / `sync_page` 等）——多为展示用途，评审时须逐处确认是否属「少数 UI 显示」豁免范围。**B2 目前是「约定」而非「已达标」**。

### B7 组：数据模型迁移（v2.1 新增）

数据库是**裸 sqlite3 + 手写 DDL/迁移**（非 Drift 生成）。**改表结构必须同步三处，缺一即为 bug**：

| # | 规则 |
|---|---|
| B7.1 | 改列必须同时改 **`_ddlXxx` 建表语句**（新装路径）与 **`_migrate()` 迁移步**（老库路径） |
| B7.2 | `kSchemaVersion` 必须逐级 +1；**已发布的号冻结，只能追加不得复用或回退** |
| B7.3 | `_migrate()` 内**每个 `ALTER` 前必须先用 `PRAGMA table_info(表)` 判列是否存在**——`_init()` 是先建表再迁移，新装库建表时已带该列，无条件 ALTER 会报 `duplicate column` |
| B7.4 | 迁移仅允许 `CREATE TABLE` / `CREATE INDEX` / `ALTER TABLE ... ADD COLUMN`（带默认值）；**禁止改列类型、改主键、`DROP COLUMN`、重命名** |
| B7.5 | 每步迁移在单独事务内完成，失败整体回滚；**迁移前无条件 `VACUUM INTO` 一致性备份**（《06》B4） |
| B7.6 | 新增索引若依赖新列（如 `idx_entry_parent` 依赖 `parent_id`），**必须与迁移步同批次提交**，不得先行加入 `_indexes`（列不存在时执行会失败） |
| B7.7 | 每个迁移步必须有对应测试（载旧快照 → 升级 → 校验结构与行数），**当前为空白**（见 §7） |

> 迁移步的完整可执行规格与逐版本清单以《08》§9.1 为准。
> **典型反面教材**：`split_role` / `parent_id` / `is_rigid` 三列曾在文档中被记为「已完成」，但当时代码中**不存在**——这正是 B7.1/B7.2 未被遵守的结果。（**2026-10-15 复核：该三列已于 v4/v10 落库**，此处保留为流程教训：文档状态必须由代码反向校准，不得预设。）

### D 组：数据刷新（强制）

**写 → bump，读 → watch。禁止 pop 后手动 `refresh()`。**

```dart
// 写侧
ref.invalidateData.bumpEntryMutated();
ref.invalidateData.bumpCategoriesMutated();
ref.invalidateData.bumpAccountsMutated();
ref.invalidateData.bumpBudgetMutated();
ref.invalidateData.bumpRecurringMutated();

// 读侧 FutureProvider
final p = FutureProvider<T>((ref) async {
  ref.watch(ledgerVersionProvider);
  return load();
});
```

实现：`lib/core/refresh/data_invalidation.dart`。列表页如需立即重取可再 `ref.invalidate(provider)`。

## 8. 决策记录

1. **lint 基线改为 flutter_lints**：VGA 在本工程与 AGP9/插件链路叠加噪音大；flutter_lints + strict 已覆盖异步与 print 等红线。
2. **禁止硬编码高度**：多轮溢出（键盘 36px、分类格 7px、锁屏 1.1px）均因固定尺寸，统一改为弹性/滚动。
3. **默认主题素白**：产品反馈「不够亮、不和谐」后重做色板，素白为品牌默认。
4. **file_picker 不用第三方**：Kotlin/AGP 组合导致注册类编译失败，改为 `app/file_picker` 通道。
5. **迁移步必须判列存在（B7.3）**：`_init()` 先建表再迁移的顺导致新装库与老库走不同路径，若 `_migrate()` 无条件 ALTER 则新装即崩。此规则由 v2/v3 迁移的实战教训固化。
6. **`on Object` 而非 `on Exception` 捕获事务（B3）**：`_fromRow` 的 `as int` 断言抛 `Error` 而非 `Exception`，只捕 `Exception` 会让事务悬挂、后续写落在未结束事务里。已在 `database.dart` 落地。
